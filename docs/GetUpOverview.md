# 起き上がり動作の学習 — 手法・報酬・各版の結果（2026-10-30 時点）

KHR-3HV が床に倒れた状態から、四脚歩行（v31）の初期姿勢まで起き上がる動作を、強化学習で学ばせた記録のまとめ。
一次記録は `getup/DIARY.md`（版ごとの動機 → 変更 → 結果 → 分析）、計画と判定の基準は `docs/GetUpSim2RealPlan.md`。この資料は両者から数字を写してまとめたもの（7.1 節の実機との違いの評価だけは、この資料のために 2026-10-30 に新しく測った）。

- **採用版**: getup-v5 dcthr（L2・個体差ありで 3 シード 87.4 / 90.6 / 96.4 %、トルクの 99 % 点 52〜54 %）。中身は 5.8 節
- **今の状態**: 2026-10-23 のユーザーの決定で**保留**（「まず卒論の骨組みを完成させる」）。実機ではまだ起き上がらせていない
- **実機で可能か**（2026-10-30 の確かめ、7 節）: シミュレーションでは、実機との主な違い（トルクの上限がない・電圧の低下・遅れ 40 ms）に耐える。ただし今すぐには実機で動かせない（電源を入れて動かすデプロイヤが未実装など）
- 成功率は、断りがない限り「L2 の評価用の全 1,591 状態・個体差と観測ノイズあり・決定的な方策・8 秒以内」の値

## 1. 課題

### 1.1 目標の動作と範囲

床に倒れた状態から、**v31 の四脚歩行の初期姿勢**（胴体を前に 90° 倒し、胸が床を向き、胴体の高さ 0.193 m、前腕と足の 4 点で接地）まで起き上がり、そこで静止する。
歩行への引き継ぎは、できれば行う（必須ではない）。

範囲は、最初の胴体の向き u0 で区切る。u は重力の向き（胴体の座標）の x 成分で、胸が床を向いている度合いを表す（四脚の姿勢と平らなうつ伏せで +1、横向きで 0、仰向けで −1。ヨーにはよらない）。

| 段階 | 最初の状態 | 位置づけ | 学習した版 |
|---|---|---|---|
| L0 | 四脚の公称姿勢の近く（関節 ±0.1〜0.5 rad、傾き ±10〜40°） | カリキュラムの入口 | v1〜v5 |
| L1 | u0 ≥ 0.9（平らなうつ伏せ、手足はランダム） | — | v1〜v5 |
| **L2** | **u0 ≥ 0.5（四脚の向きから 60° 以内、手足はランダム）** | **必達（実機でも）** | v1〜v5 |
| L3 | u0 ≥ 0（横向きまで）、歩行中の転倒 | 時間があれば | まだ |
| L4 | すべて（仰向けからの寝返りを含む） | 時間があれば | まだ |

### 1.2 成功の判定（シミュレーションと実機で同じ定義）

**8 秒以内に、次の 5 つをすべて 1 秒続けて満たす**（1 回目の試行で）。

| 条件 | しきい値 | ねらい |
|---|---|---|
| 胴体の傾き | 四脚の向きから 15° 以内（u > 0.966） | 胸が床を向いている |
| 関節角 | 22 関節すべてが公称姿勢から 0.3 rad 以内 | 歩行の方策に引き継げる姿勢（v31 は 0.5 rad までずれても引き継げた） |
| 胴体の高さ | 0.175 m 以上（公称 0.193 m の約 9 割） | 持ち上がっている |
| 接地 | 前腕と足以外（胴体・胸・頭・肩・上腕・股関節・大腿の 13 リンク）が床に触れない | 体を支点にしていない |
| 静止 | 胴体の角速度 0.5 rad/s 未満 | 跳ねたり揺れたりしていない |

- 8 秒は「急いで起き上がれ」という意味ではない。起き上がり自体は中央値で 1〜3 秒で終わる（5.4 節）。2026-10-15 に 16 秒に延ばした（v3）が、同じ日に 8 秒に戻した。
- 報酬の `success` 項は「その瞬間に 5 つを満たすか」を使う（1 秒続けたかは評価だけで数える。報酬に入れると状態だけで報酬が決まらなくなるため）。

## 2. 学習の手法

### 2.1 全体

| 項目 | 内容 |
|---|---|
| シミュレータ | Genesis（GPU）、4096 環境を並列 |
| 学習アルゴリズム | PPO（rsl-rl 5.4）、非対称アクター・クリティック（クリティックは特権観測も使う） |
| 制御周期 | 50 Hz（0.02 s）。方策の出力は 1 周期遅れて PD の目標角になる |
| 関節 | 22 関節すべて（腕も脚も） |
| 学習の長さ | 1500 イテレーション（v3 だけ 3000）。1 本 約 27 分（56 イテレーション/分） |
| 1 エピソード | 8 秒（400 周期）。v3 だけ 16 秒 |

### 2.2 機体モデルと物理

- 機体モデル: 歩行と同じ機体モデルから、衝突形状だけを細かくした起き上がり用の複製を作った（`getup/tools/make_getup_urdf.py`、`../assets` に書き出し、git には入れない）。
  凸包のままだと胸・前腕・太ももの付け根などが実物より最大 17〜38 mm 外側に出ていたので、凸な部品 57 個に分け、はみ出しを 3.7〜5.2 mm にした。質量（1.6 kg）と四脚の姿勢の高さは元と同じ。v31 はこの複製でも同じに歩く。
- サーボ: PD 制御（剛性 25 N·m/rad、減衰 0.5 N·m·s/rad、アーマチュア 0.01）、トルクの上限 1.373 N·m（最大トルク）。歩行 v31 と同じ。
- 床の摩擦 0.5（機体のリンクごとの比率を個体差で変える）。

### 2.3 初期状態のバンク

学習の初期状態は、ランダムな姿勢から機体を落として作った状態の集まり（`getup/gen_init_states.py` → `getup/data/banks/bank_v1.pt`）。

- 作り方: 胴体の向きを「半分は全方向に一様、半分はうつ伏せ ±60°」、関節を「半分は公称 ± 可動域の 3 割、半分は可動域の中で広く」でランダムにし、
  自分の体に 5 mm 以上めり込む姿勢は捨てる。5〜15 cm の高さから落とし、2.5 秒落ち着かせる（半分は脱力、半分は目標角を保持）。止まったものだけを採る（採用率 約 55 %）。
- 数: 主 20,000 個（u0 ≥ 0.9 が 3,775、≥ 0.5 が 7,966）、公称姿勢の近く 4,000 個。ほかに**評価用 4,800 個は学習に使わない**（L0 825・L1 758・L2 1,591）。
- 報酬の高さの基準もバンクから取った: 四脚の公称姿勢で胴体 0.1932 m・胸 0.1937 m、うつ伏せの中央値で胴体 0.0858 m・胸 0.0814 m。

### 2.4 カリキュラム

#### なぜ使うか

倒れたランダムな姿勢から学び始めると、四脚の姿勢に近づくまで報酬（高さ・姿勢・成功）がほとんど得られない。
そこで、**ゴールの姿勢の近くから始めて「四脚で立って止まる」を先に覚えさせ**、できるようになったら難しい初期状態に広げる。

#### 段階の中身（初期状態のバンクから）

| 段階 | 選び方 | 学習用 | 評価用 | 中身 |
|---|---|---|---|---|
| L0 | 公称姿勢の近く（関節 ±0.1〜0.5 rad、傾き ±10〜40° から落とした状態） | 3,175 | 825 | 79 % は u0 ≥ 0.9。ただし 15 % は落ちて仰向け寄り（u0 < 0）になっている |
| L1 | 主のバンクで u0 ≥ 0.9（平らなうつ伏せ、手足はランダム） | 3,017 | 758 | — |
| L2 | 主のバンクで u0 ≥ 0.5（四脚の向きから 60° 以内） | 6,375 | 1,591 | L1 の状態を含む（47 %） |

- L3（横向き・歩行中の転倒）と L4（仰向け）は計画だけで、作っていない。
- L0 の仰向け寄りの状態は、寝返りが学習の範囲外なので起き上がれない。L0 の評価の成功が 74 % どまりなのはこのため。

#### リセットのときにどの段階から選ぶか

エピソードが終わるたびに、15 % を L0、15 % を合格済みの段階から一様（L0 を含む）、70 % を今の段階から選び、その段階の状態から一様に 1 つ取る。
今の段階ごとの実際の割合は次のとおり。

| 今の段階 | L0 | L1 | L2 |
|---|---|---|---|
| L0 | 100 % | — | — |
| L1 | 30 % | 70 % | — |
| L2 | 22.5 % | 7.5 % | 70 % |

L2 の段階では、L2 の中に L1 の状態が 47 % あるので、学習のリセットのおおよその内訳は「平らなうつ伏せ（u0 ≥ 0.9）41 %・傾いた状態（0.5 ≤ u0 < 0.9）37 %・L0 22.5 %」になる。
合格済みの段階を混ぜ続けるのは、前に覚えた初期状態を忘れないため。

#### 段階が上がる条件

| 条件 | 内容 |
|---|---|
| 合格の割合 | 今の段階から始めたエピソードの直近 2000 回のうち、「最後の 1 秒、角速度以外の条件（向き・関節角・高さ・端以外の接地なし）を満たして立っていた」割合が 0.75 以上 |
| 間隔 | 前に上がってから 200 イテレーション以上 |
| 上がったとき | 合格の記録を空にして数え直す。**下がることはない** |

- **200 イテレーションの下限が、実際には決め手になる**。1 イテレーションで約 246 回のエピソードが終わり（4096 環境 × 24 周期 ÷ 400 周期）、その約 7 割が今の段階なので、2000 回の記録は約 12 イテレーションでたまる。覚えの速い学習は最短の 200 と 400 で上がる。
- **合格に角速度を入れない理由**: 学習中の方策は探索のゆらぎ（標準偏差 0.3 以上）を足した行動で動くので、胴体が揺れて角速度 0.5 rad/s を 1 秒保てない。
  v1 の小試験（200 イテレーション、L0）では、同じ方策でゆらぎつき 0 %、決定的 33 %、行動 0 で 79 % だった。成功の判定で数えると L0 から上がらないので、
  2026-10-14 にユーザーが選んだ案 1 で、合格だけを「角速度以外の条件で立っている」にした。評価と実機の成功の定義（角速度を含む）は変えていない。
- その他: クリティックは特権観測として今の段階を受け取る。学習の最初はエピソードの長さをばらして始める（終わる時刻がそろわないように）。評価は段階を固定し、評価用の全状態を決定的な方策で 1 回ずつ動かす。

#### 実際に上がった時刻と最後の成功率

| 構成 | L1 → L2 のイテレーション（シード 1 / 2 / 3） | L2 の成功（シード 1 / 2 / 3） |
|---|---|---|
| v1 | 400 / 409 / 400 | 87.7 / 81.5 / 84.6 % |
| v2 | 598 / 876 / 483 | 86.3 / 75.1 / 51.3 % |
| v3 | 上がらない（シード 1 だけ） | 35.9 % |
| v4 cap90 | 400 / 400 / 478 | 85.7 / 91.3 / 84.0 % |
| v4 smooth | 1431 / 上がらない / 上がらない | 59.7 / 34.6 / 25.0 % |
| v4 ent0 | 400 / 上がらない / 上がらない | 98.2 / 33.5 / 32.2 % |
| v4 delta03 | 400 / 448 / 400 | 97.7 / 96.2 / 97.2 % |
| v5 dc | 400 / 400 / 400 | 96.0 / 97.0 / 97.9 % |
| v5 dcthr | 846 / 902 / 675 | 87.4 / 90.6 / 96.4 % |

（L0 → L1 は全試行で最短の 200。出典は各試行の `logs/<試行>/run_info.json` の `promotions`）

1. **L2 に上がらなかった試行は、L2 の成功が 25〜36 % にとどまる**（v3、smooth と ent0 のシード 2・3）。L1 で覚えたことだけで傾いた状態に少し対応できる程度。
2. **上がらなかった試行は、どれも探索の標準偏差が 0.02〜0.06 まで縮んでいた**。方策が新しい動きを探さなくなると合格の割合が 0.75 に届かず、カリキュラムは止まる。
   下がる仕組みも別の手に切り替える仕組みもないので抜け出せない。揺れのペナルティとエントロピー 0 を避けたのはこのため。
3. **dcthr は L2 に上がるのが遅い**（675〜902、dc はすべて 400）。トルクのペナルティを強めた分、最後の 1 秒に立ち続けることを覚えるのに時間がかかったとみられる（未確認）。
4. **上がった時刻と最後の成功率の関係は弱い**。dcthr は最も早いシード 3 が最も高い（96.4 %）が、v2 はシード 3 が 2 番目に早いのに最も低い（51.3 %）。
   ただし終わり近くで上がった smooth のシード 1（1431）は 59.7 % で、L2 での学習の時間が足りなかったとみられる。

#### 今のカリキュラムの弱いところ

| 弱いところ | 影響 |
|---|---|
| 合格の条件が緩い（角速度を見ない） | 揺れながら立つ段階で上に上がれる。最後の成功率（角速度を含む）との差は、立った後の揺れとして残った（v1・v2 の失敗の大半） |
| 下がらない・止まったときの手がない | 探索が縮んで止まった試行を救えない |
| L0 の割合が多い | L2 の段階でも 22.5 % が L0。学習の範囲外の仰向け寄りの状態（15 %）も入っている |
| L2 の中で難しさを調整しない | u0 はバンクのまま一様に選ぶ。苦手な状態を多く選ぶ仕組みはない |
| 実機との関係 | 実機は手で置いた脱力のうつ伏せから始めるので、ほぼ L1 の種類の状態。L2 はそれを含むので範囲は足りている。L3・L4 に広げるときは、計画どおり段階ごとの判定（反転 → 持ち上げ → 保持）が要る |

### 2.5 観測

アクター（方策）の観測は 184 次元で、**実機で得られる量だけ**を使う。

| 位置 | 内容 |
|---|---|
| 0〜2 | 胴体の角速度 × 0.25（±5.72 rad/s で切る） |
| 3〜5 | 重力の向き（胴体の座標） |
| 6〜27 | 関節角 − 公称姿勢 |
| 28〜49 | 関節速度 × 0.05（観測した関節角の 50 Hz の差分。実機と同じ計算） |
| 50〜71 | 前の周期に実際に送った目標角 − 公称姿勢（後処理の後の値） |
| 72〜183 | 過去 4 周期の [角速度, 重力, 関節角 − 公称]（28 × 4） |

- 歩行と違い、指令・歩容の位相・累積ヨー角誤差は入れない。
- クリティックは、ほかに特権観測 99 次元（ノイズのない状態、胴体の速度、胴体と胸と足の高さ、各リンクの床との接触、個体差の値、カリキュラムの段階）を使う。
- リセット直後の観測は、バンクの状態から計算し直す（公称姿勢の値を使い回さない）。

### 2.6 行動と後処理

行動は 22 次元（±1 で切る）。目標角にするまでの処理は `khr_common/action_post.py` にあり、**学習環境と実機のデプロイヤで同じ関数を使う**。

| 順 | 処理 | 値 |
|---|---|---|
| 1 | 写像: 公称姿勢を中心に、+ 側と − 側で幅の違う区分線形の写像（可動域の端までの距離 − 0.03 rad、最大 1.2 rad） | 公称姿勢の近くで可動域の端に近い関節（股関節ピッチは下限まで 8.6°）があるので、対称な写像だと片側が切れて勾配が消える |
| 2 | 速さの制限: 前の目標角から 1 周期に動ける量 | v1〜v4 は 0.06 rad/周期（3 rad/s）。v4 の delta03 と v5 は 0.03 |
| 3 | 可動域: 可動域の 0.03 rad 内側に収める | — |
| 4 | gap（v2 から）: 観測した関節角 ± 0.05 rad に収める | P の項が最大トルクの 91 % を超えないように |
| 5 | 遅れ: 1 周期遅れて PD の目標角になる（シミュレーションだけ） | 実機の通信の遅れを模す |

リセットのときと実機の開始のときは、前の目標角と遅れの記憶を、測った関節角で初期化する（行動 0 から始めると、最初の目標角が 2〜3 rad 跳ぶため）。

### 2.7 個体差（ドメインランダム化）と観測ノイズ

| 項目 | 範囲 |
|---|---|
| 摩擦 | 0.6〜1.4 倍 |
| 胴体の質量 | ±0.08 kg（歩行の −0.1〜+0.5 kg は使わない。起き上がりでは物理的にできない条件を作りうるため） |
| 重心 | ±1 cm |
| サーボの原点オフセット | ±0.02 rad（方策から見えない。実際の角度 = 指令 + オフセット、返る角度 = 実際 − オフセット） |
| IMU の取り付け誤差 | 0〜3°（体ごとに一定。10/13 の実機の歩行でのずれがこの程度だった） |
| 観測ノイズ | 角速度 0.1、重力 0.05、関節角 0.01 rad（歩行の 0.05 rad より小さい。関節速度を差分で作るので、0.05 rad だと ±5 rad/s の雑音になる） |

### 2.8 終了とエピソード

- 打ち切りはシミュレーションの破綻だけ（その周期の報酬を −20 にしてリセット）。転んでもエピソードは続ける。生存のボーナスは置かない。
- 時間切れは価値で継ぎ足す（`time_outs`）。成功した後も最後まで回し、保つことも学ばせる。

### 2.9 PPO の設定

| 項目 | 値 |
|---|---|
| ネットワーク | アクター・クリティックとも [256, 128, 64]、ELU、観測の正規化あり |
| 行動の分布 | ガウス分布、標準偏差の初期 0.5（全関節で 1 つ） |
| 学習率 | 1e-3（KL で自動調整、目標 0.01） |
| γ・λ | 0.99・0.95 |
| クリップ | 0.2 |
| エントロピーの係数 | 0.005（v3 と v4 の ent0 は 0） |
| 1 回の更新 | 24 周期 × 4096 環境、5 エポック × 4 ミニバッチ |
| 行動の平均の範囲外のペナルティ（v2 から） | 損失に 0.01 × Σ（平均が ±1 の外に出た分の 2 乗）を足す（`getup/ppo_bound.py`。rsl-rl 5.4.0 の PPO の更新に 1 行足した版） |

## 3. 報酬

報酬は毎周期、各項 × 重み × 0.02 s の和。重みは 0.02 s を掛ける前の値。v1〜v5 で**式は変えていない**。版で変えたのは重み・トルクのペナルティの閾値・項の有無だけ。

### 3.1 記号

| 記号 | 意味 |
|---|---|
| u | 重力の向き（胴体の座標）の x 成分。四脚の姿勢・うつ伏せで +1、横向き 0、仰向け −1 |
| ĥ（胴体・胸） | 高さを 0〜1 にしたもの: clip((h − うつ伏せの高さ) / (四脚の高さ − うつ伏せの高さ), 0, 1) |
| q、q* | 関節角（22）、四脚の公称姿勢（歩行 v31 の初期姿勢） |
| σ(x) | シグモイド関数 1 / (1 + exp(−x)) |
| 成功（その瞬間） | 1.2 節の 5 条件を今の周期で満たす |
| a | 方策の行動（±1 で切った値） |
| τ_lim | 最大トルク 1.373 N·m（シミュレーションの上限を 90 % に下げた版でも、ここは仕様の値） |

### 3.2 項の式とねらい

| 項 | 式 | ねらい |
|---|---|---|
| height | σ((u − 0.7) / 0.05) × ½(ĥ胴体 + ĥ胸) | 胴体と胸を四脚の高さまで持ち上げる。胸を入れて「お尻だけ上げる」形を防ぐ。胸が下を向いているときだけ |
| upright | ((u + 1) / 2)² | 胸を床の方へ向ける（うつ伏せは最初から満点。横向き・仰向けからの寝返り用） |
| pose | exp(−mean_j (q_j − q*_j)² / 0.25²) × σ((u − 0.9) / 0.03) × clip((h胴体 − 0.15) / 0.03, 0, 1) | 実際の関節角を公称姿勢に近づける。向きと高さがそろったときだけ（伏せたまま関節だけ合わせるのを防ぐ） |
| success | 成功（その瞬間）なら exp(−(‖v‖² + 0.1‖ω‖²) / 0.05)、そうでなければ 0（v は胴体の速度、ω は角速度） | 四脚の姿勢で静止する（跳ねて高さを稼ぐのを防ぐ） |
| body_ground_contact | 端以外の 13 リンクの床との接触の数 × 1[胴体の高さ > 0.12 m] | 頭や胴体を支点にしない（持ち上がってから） |
| torque_limits | Σ_j max(abs(τ_j) / τ_lim − 閾値, 0)² | 閾値（0.85、dcthr は 0.60）を超えるトルクを抑える |
| dof_vel_limits | Σ_j max(abs(q̇_j) − 6.0, 0) | 関節速度 6 rad/s 超を抑える |
| dof_pos_limits | 可動域の端から 0.03 rad 以内に入った関節の数 | 可動域の端に打ち付けない |
| action_rate | Σ_j (a_t − a_{t−1})² | 行動の急な変化を抑える |
| action_smoothness2 | Σ_j (a_t − 2a_{t−1} + a_{t−2})² | 毎周期の向きの反転を抑える（v3 と v4 の smooth だけ） |

## 4. 評価の方法

| 道具 | 何を測るか |
|---|---|
| `getup/eval_getup.py` | 評価用の状態（学習に使っていない）の段階ごとの全状態を、決定的な方策で 8 秒ずつ 1 回。個体差あり（学習と同じ）と公称の 2 条件。成功率（Wilson の 95 % 区間）、累積の成功の曲線、最後に立っている率、トルク（99 % 点・90 % 以上の時間・100 % に達した関節と時刻）、関節速度、破綻。**段階ごとに 6 エピソードの動画を毎回撮る**（`media/videos/getup/`） |
| `getup/tools/hold_analysis.py` | 立った後（L2 の 256 状態、12 秒のうち 8〜12 秒）の揺れ: 送る目標角の毎周期の変化、関節速度の周波数、胴体の移動、手足の付け外し、立っている間の関節ごとの平均トルク。目標角を固定したとき（方策を止めて PD と物理だけ）とも比べる |
| `getup/tools/dr_factor_eval.py` | 個体差・ノイズを 1 つずつ入れて成功率を測る。トルクの上限や速さの制限を、学習し直さずに評価のときだけ変えることもできる |
| `getup/tools/sat_breakdown.py` | トルクが 100 % に達した瞬間の、目標と関節角の差の内訳（制限の分・ノイズ・遅れの間に押し戻された分） |

判定の基準（計画書 §4.8）: ゲート S（11/1）はシミュレーションで L2 ≥ 70 %、次へ進む条件は L2 ≥ 90 %（個体差あり）。トルクは 99 % 点 < 90 %、90 % 以上の時間 ≈ 0（シードごとの最悪値で見る）。
**1 シードでは結論を出さない**（v2 は同じ設定でシードによって L2 が 86 % から 51 % まで割れた）。

### 5.2 getup-v1（2026-10-14）

**結果**（シード 1、評価用の全状態）:

| 段階 | 個体差あり | 公称 | 最後に立っている | 成功までの時間（中央） | トルクの 99 % 点 |
|---|---|---|---|---|---|
| L0 | 73.9 % | 77.1 % | 81.3 % | 1.42 秒 | 74.2 % |
| L1 | 87.5 % | 89.2 % | 95.8 % | 2.10 秒 | 91.1 % |
| L2 | 87.7 % | 90.6 % | 96.1 % | 2.22 秒 | 97.5 % |

- 3 シードの L2: 87.7 / 81.5 / 84.6 %（平均 84.6 %）。ゲート S（L2 ≥ 70 %）は満たすが、L1 ≥ 90 % には届かない。
- L0 が低いのは、公称姿勢の近くから落とすと仰向け寄り（u0 < 0）になる状態があり、そこは学習していないため（u0 ≥ 0.9 の状態は 88.9 %）。
- L2 の u0 の区間別はほぼ同じ（86.5〜89.3 %）。うつ伏せからの傾きにはほとんどよらない。

**分析**:

1. **失敗の 3 分の 2 は「立っているのに揺れが収まらない」**。最後の 1 秒に立っている体は 95.8 %（L1）で、成功の 87.5 % との差は角速度の条件。
2. **方策が「全開か全閉か」で動いている**。行動の平均が ±1 の外にある時間が 90 %。±1 で切るので探索のゆらぎが効かず、エントロピーの項で標準偏差がペナルティなしに増え続けた（0.30 → 0.92）。決定的な方策 89.5 % に対し、ゆらぎつきは 96.1 %。
3. **トルクがどのエピソードでも一度は 100 % に達する**（開始から中央値 0.08 秒）。行動 0（公称姿勢へ戻すだけ）でも達する。剛性 25・上限 1.373 N·m では、目標と関節角の差が 0.055 rad を超えると上限に張り付き、目標角は 1 周期 0.06 rad 動くので、床に押さえられた関節はすぐにこの差を超える。

### 5.3 getup-v2（2026-10-14）

v1 の 2 と 3 を直した: 行動の平均の範囲外のペナルティ（係数 0.01）と、送る目標角を観測した関節角 ± 0.05 rad に収める gap。

| L2・個体差あり | v1（シード 1） | v2（シード 1） |
|---|---|---|
| 成功 | 87.7 % | 86.3 % |
| 公称 | 90.6 % | 95.5 % |
| 成功までの時間（中央） | 2.22 秒 | 4.52 秒 |
| トルクの 99 % 点 | 97.5 % | 80.0 % |
| 100 % にいる時間 | 0.93 % | 0.16 % |
| 100 % に一度でも達したエピソード | 100 % | 98 % |
| 行動の平均が ±1 の外 | 88.8 % | 31.6 % |

**分析**:

- 全開・全閉の動かし方はほぼ消えた。トルクの 99 % 点は 80 % に下がったが、100 % に一度は達するエピソードは 98 % のまま。
- 残った 100 % の主因は、**目標を決めてから実行されるまでの 1 周期に、荷重で関節が押し戻されること**（`sat_breakdown`: 差の内訳の中央値は、制限の分 0.037 rad、押し戻された分 0.028 rad、ノイズ 0.001 rad）。100 % に達した瞬間の関節はほとんど止まっていた（中央値 0.18 rad/s）。速く動くからではなく、体重を支える姿勢の負荷で起きる。
- **3 シードで割れた**: 86.3 / 75.1 / 51.3 %。シード 3 は立った後の震えが強く、静止の判定のやり直しが平均 35.6 回あった。
- 弱点は「個体差 ＋ 関節角の観測ノイズ」の組み合わせ（92.2 → 86.2 %。どちらか単独では 1〜3 pt）。gap の中心に、ノイズを含む観測した関節角を使うためと考えられる（未確認）。
- 評価のときだけ gap を 0.03 に絞ると成功は 3.5 % に落ちた。今の方策は上限近くのトルクがある前提の起き上がり方で、絞るだけでは立てない。

### 5.4 立った後の揺れ（v1・v2 の分析、2026-10-15）

ユーザーの指摘（動画で、立った後に小刻みに震え、少しずつ動いている）を受けて調べた。

| 立った後（8〜12 秒） | v1 | v1 目標角を固定 | v2 | v2 目標角を固定 |
|---|---|---|---|---|
| 送る目標角の変化（RMS） | 0.060 rad/周期 | 0 | 0.055 rad/周期 | 0 |
| 関節速度の主な周波数 | 20〜25 Hz に 99 % | — | 10〜25 Hz | — |
| 胴体の移動（中央） | 3.7 mm/s | 1.0 | 8.6 mm/s | 1.8 |
| 手足の付け外し | 8.6 回/s | 0.4 | 9.9 回/s | 0.45 |
| トルクの 99 % 点 | 69 % | 35 % | 78 % | 33 % |

- **揺れの原因は方策の出力**。立った後も目標角を毎周期ほぼ制限いっぱいに行き来させている（1 周期ごとに向きが反転する 25 Hz）。観測ノイズや個体差を切っても変わらない。
- 目標角を固定すると止まる。揺れで手足が床から離れたり着いたりを毎秒 8〜10 回くり返し、そのたびに少しずつ滑って移動する。
- 揺れはトルクも押し上げる（立っているだけで 99 % 点 68〜79 %、固定すると 33〜35 %）。
- 学習の目的に、これを止める理由がない（行動の変化のペナルティが小さく、成功の条件の角速度 0.5 rad/s は揺れていても満たせる）。

**時間との関係**: 起き上がり自体は 8 秒よりずっと早く終わる（v2 は 98 % が 8 秒以内に立ち、姿勢ができるのは中央 2.4 秒）。8 秒での失敗の大半は、立った後の震えで 1 秒の静止の判定がやり直しになったもの。

### 5.5 getup-v3（2026-10-15、不合格）

ユーザーの判断（「速く起き上がる必要はない。トルクが 100 % に張り付くほうが問題」「案をまとめて入れ、後から切り分ける」）で、5 つの変更を同時に入れた: 16 秒、トルクの上限 90 %、速さの制限 0.03、揺れのペナルティ（action_rate −0.02、2 階差分 −0.01）、エントロピー 0。

| 個体差あり | L0 | L1 | L2 |
|---|---|---|---|
| 成功（16 秒） | 80.5 % | 58.1 % | **35.9 %** |

- **L1 で止まった**: L2 に一度も上がらなかった。行動の標準偏差が 0.50 → 0.02 に縮み、押し上げる動きを探さなくなった。失敗の動画では、横に丸まったまま、または脚を畳んで座ったまま止まる。
- 学習し直さない診断: v2 の方策をトルクの上限 90 % で動かしても、立つ率は 0.2〜1.0 pt しか下がらない。v3 の方策を上限 100 % に戻しても変わらない。→ **上限 90 % が立てない原因ではない**。
- 立てた回は震えにくい（静止の判定のやり直し 平均 1.3 回）。ただし立っている間、左右の股関節のヨーを上限（仕様の 90 %）に押し付けている（平均 84〜86 %）。
- v2 から再開し、v3 の変更を 1 つずつ足して切り分けることにした（v4）。

### 5.8 dcthr とは（採用版の中身）

**getup-v5 で採用した構成の名前**。v2 に、効いた 3 つの変更を足したもので、名前は 3 つの頭文字をつないでいる（「dc」は d と c だけを足した構成）。

| 文字 | 元の名前 | 変えたこと | 値 |
|---|---|---|---|
| d | delta03 | 送る目標角の速さの制限 | 0.06 → **0.03 rad/周期**（3 → 1.5 rad/s） |
| c | cap90 | シミュレーションのトルクの上限 | 仕様の 100 % → **90 %**（1.236 N·m） |
| thr | thr60 | トルク上限のペナルティの閾値 | 最大トルクの 85 % → **60 %**（歩行 v31 と同じ） |

土台の v2 は、v1 の 2 つの問題を直した版: 行動の平均の範囲外のペナルティ（係数 0.01。v1 は行動が「全開か全閉か」になり探索のゆらぎが効かなかった）と、
gap（送る目標角を観測した関節角 ± 0.05 rad に収める。目標と関節角の差が開いてトルクが上限に張り付くのを抑える）。

**3 つの要素が効いた理由**:

- **d（速さの制限 0.03）**: v4 で 1 つずつ足した 4 つのうち、いちばん効いた（L2 の成功が 3 シードとも 96 % 以上）。目標角が 1 周期に動ける量が半分になり、立った後に目標角を毎周期行き来させる揺れが小さくなった。
  欠点は、トルクを上限まで使い、立っている間に股関節のヨーを約 90 % で押し続けること。
- **c（トルクの上限 90 %）**: 方策が仕様の 90 % を超えるトルクを使えない中で起き上がり方を学ぶ。成功は下がらなかった（v2 の 70.9 % → 87.0 %）。欠点は d と同じく上限まで使い切り、股関節のヨーを 85〜87 % で押し付けること。
  実機のサーボにはこの 90 % の頭打ちがない（7.1 節）。
- **thr（ペナルティの閾値 60 %）**: d と c の押し付けを消すために足した。押し付けが起きていたのは、閾値 85 % では 85〜90 % で押し続けてもペナルティが 90 % で 1 関節あたり 0.0025 × 重み 10 しかかからず、ほとんど効いていなかったため。
  60 % にすると、立っている間の股関節のヨーは 26 % 以下、トルクの 99 % 点は 52〜54 % になった。

**dc との比較**（5.7 節の表）: 成功の基準（平均 ≥ 90 %、最低 ≥ 85 %）はどちらも満たした。採用は「立っている間のトルクが低い方」と事前に決めていたので dcthr。
成功率では dc（97.0 %）にやや劣る（91.5 %）代わりに、実機でのサーボの発熱と負荷が小さい。L2 に上がる時刻も dc より遅い（2.4 節）。

| dcthr の設定 | 値 |
|---|---|
| 環境 | `getup/envs/getup_env3.py`（学習は `getup/train_getup4.py` の `--add cap90 delta03 thr60`） |
| エピソード・イテレーション | 8 秒・1500 |
| 行動の平均の範囲外のペナルティ・gap | 0.01・0.05 rad |
| 速さの制限・シミュレーションのトルクの上限 | 0.03 rad/周期・仕様の 90 % |
| トルク上限のペナルティ | 重み −10、閾値 0.60 |
| action_rate | −0.005（揺れのペナルティの強化はしない。v4 で害と分かったため） |
| エントロピーの係数 | 0.005（0 にしない。v4 でシードによって探索が止まると分かったため） |
| ほかの報酬 | height +2、upright +1、pose +2、success +3、body_ground_contact −1、dof_vel_limits −0.5、dof_pos_limits −5 |
| 実機のデプロイヤの既定 | `getup5-dcthr-s3`（model 1499） |

### 5.9 版を通して分かったこと

1. **立つことより、立った後に静かに止まることが難しい**。v1・v2 は 95〜98 % が立てていたが、失敗の大半は立った後の震え（1 周期ごとに目標角を行き来させる）だった。
2. **トルクの 100 % は、時間や速さではなく姿勢の負荷と 1 周期の遅れで起きる**。ゆっくりにしても、100 % に一度は達するエピソードは減らなかった。
3. **探索を縮める変更は危ない**。揺れのペナルティとエントロピー 0 は、シードによって標準偏差が 0.02〜0.06 まで縮み、L1 から上がらなくなった。
4. **速さの制限（0.03 rad/周期）がいちばん効いた**。成功は 3 シードとも 96 % 以上になり、震えも減った。ただし単独ではトルクを上限まで使い、股関節のヨーを押し付ける。
5. **押し付けは、トルクのペナルティの閾値を下げると消えた**（0.85 → 0.60）。歩行で 60 % を選んだ理由と同じ働き（目標角を関節角から離して PD を飽和させる動きを抑える）が、起き上がりでも見えた。
6. **シード間のばらつきが大きい**。v2 は 51〜86 %、ent0 は 32〜98 %。どの判断も 3 シードがそろってから行った。

## 7. 実機で可能か（2026-10-30 の確かめ）

### 7.1 シミュレーションで実機との違いに耐えるか

採用版 dcthr の 3 シードを、実機との主な違いを 1 つずつ入れた条件で評価した（`getup/tools/dr_factor_eval.py`、L2 の評価用の状態から決まった乱数で 256 個、個体差と観測ノイズあり、8 秒、決定的な方策）。
遅れの周期数は評価のときだけ変えられるようにした（`getup_env3` の `action_latency_steps`。既定 1 は学習と同じ）。結果は `experiments/getup/eval/dr_factors_getup5-dcthr-s*_1499_feas_*.json`。

| 条件 | ねらい | 成功（シード 1 / 2 / 3） | 平均 | 成功の時刻（中央） | 100 % に一瞬でも達したエピソード |
|---|---|---|---|---|---|
| 学習と同じ（上限 90 %、遅れ 1 周期 = 20 ms） | 基準 | 86.3 / 87.1 / 94.9 % | 89.5 % | 3.8〜3.9 秒 | 0 %（上限 90 %） |
| 上限 100 % | 実機のサーボには 90 % の頭打ちがない | 84.4 / 89.1 / 94.9 % | 89.5 % | 3.8〜3.9 秒 | **41〜49 %** |
| 上限 80 % | 電圧の低下（最大トルクは電圧にほぼ比例） | 87.9 / 88.3 / 97.7 % | 91.3 % | 3.8〜3.9 秒 | 0 % |
| 上限 70 % | 同上 | 88.3 / 88.7 / 96.9 % | 91.3 % | 3.9〜4.0 秒 | 0 % |
| 上限 60 % | 同上 | 88.7 / 87.1 / 96.9 % | 90.9 % | 4.1 秒 | 0 % |
| 遅れ 2 周期（40 ms） | 実機の実効の遅れ（歩行の比較では学習環境より約 20 ms 長い） | 87.5 / 87.1 / 99.2 % | 91.3 % | 4.8〜5.0 秒 | 0 % |
| 遅れ 3 周期（60 ms） | さらに遅いとき | 70.7 / 71.5 / 85.2 % | **75.8 %** | 5.8〜5.9 秒 | 0 % |
| 上限 80 % ＋ 遅れ 2 周期 | 2 つが重なったとき | 91.4 / 88.7 / 98.0 % | 92.7 % | 4.9〜5.2 秒 | 0 % |

（256 状態なので、全 1,591 状態の評価（5.7 節）とは 1〜2 pt 違う。二項の標準誤差は約 2 pt。シミュレーションの破綻は全条件で 0）

1. **トルクには大きな余裕がある**: 上限を仕様の 60 % まで下げても成功は変わらない（上限に張り付く時間は 1.4〜1.7 % に増える）。
2. **ただし上限を外すと、約半分のエピソードで一瞬 100 % に達する**（エピソードの最大の中央値 96〜99 %、90 % を超える時間は全体の 0.04 %）。
   起き上がりに要るトルクではなく、一瞬の山（接触や 1 周期の遅れの間の押し戻し）とみられる。実機ではサーボの保護（電流制限）が先に効くかもしれない（サーボの設定は未読）。
3. **遅れは 40 ms まで耐え、60 ms で落ちる**（約 14 pt 下がる）。実機の往復の遅れは改造ファームで中央 15〜20 ms、歩行の比較から見積もった実効の遅れは約 40 ms なので、耐えられる範囲だが余裕は小さい。
4. 平らなうつ伏せ（u0 ≥ 0.9、実機で手で置くときの姿勢）だけで見ても同じ傾向（学習と同じ 89.1 %、上限 100 % で 88.4 %、遅れ 2 周期で 91.9 %、遅れ 3 周期で 76.3 %）。

**注意（シミュレーションのトルクの模型の限界）**: 1 の「60 % でも立てる」をそのまま実機に当てはめてはいけない。10/28 の実機では、電池 6.92 V（11.1 V の 62 %）で、
歩行の初期姿勢まで体を持ち上げられなかった（`experiments/real/20261028_walk/README.md`）。シミュレーションのサーボは上限で切った PD だけで、
速度とトルクの関係・電流の制限・電圧の降下を入れていないので、実機で出せるトルクを多めに見ている可能性が高い。実機は AC 電源が前提で、持ち上げの試験（同定）で確かめる必要がある。
