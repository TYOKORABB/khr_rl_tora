## 2. 今日、実機なしで確かめたこと（11/7）

1. **11/6 の 4 回の記録では、サーボの通信は一度も途絶えていない。** Meridim の 88 番（エラーの欄）の下位 8 ビット（6 フレーム = 60 ms 続けて返事の無いサーボの番号）は、4 回とも全フレームで 0。
   受信もフレームが続いており、ESP32 が再起動した跡は無い。**電源が落ちる、サーボがリセットするほどの電圧の低下は起きていない。** ただし「落ちない程度に電圧が下がって力が弱まる」は否定できない。
2. **肩はずれ 2.9°（上限 0.05 rad）で押したまま、数秒間まったく動かなかった。** 1 回目の右肩は 1.5〜7.9 秒で −9.6〜−9.9°（幅 0.3°）、2 回目の左肩は 2〜5 秒で −29.4〜−30.1°（幅 0.6°）のまま。
   押し返されて戻ることも無い（減速比 312 の歯車が支えていると見る）。上限を 0.08 rad（4.6°）にした 4 回目では、右肩が 4〜7 秒に −30 → −129° まで回りきった。
   **出せる力がずれの大きさで決まっている（(c) のサーボ内の硬さ）可能性がある**（私の見立て。4 回目は姿勢も違うので、これだけでは決まらない）。重りの試験で直接測れる。
3. **Meridian のファームは、サーボに位置の指令（setPos）と脱力（setFree）しか送らない。** ストレッチ・スピード・電流制限は書き換えず、各サーボの EEPROM の値のまま動いている。
   ファームに入っている近藤のライブラリ（IcsClass V2.10）には、電流値（getCur）、温度（getTmp）、ストレッチ（getStrc）、スピード（getSpd）を読む関数がある。
   パンチ・プロテクション・電流制限の値を読む関数は無い（EEPROM を読むコマンドを自分で送れば読める見込み）。**基板に電源の電圧を測る仕組みは無い。**
4. 先行研究（`docs/RelatedWork.md` §5）: 起き上がりを実機に移した研究の強さのランダム化は ±5〜10 % で、v11b の 0.3 倍まで振った例は無い。要らない量を振ると方策が保守的になる（Xie ら）。
   KRS のプロテクションは「ロックを検知して設定の時間が経つと出力 50 %、スピード 127 のときだけ」（ICS3.5 マニュアル）。
