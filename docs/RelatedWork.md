**近藤科学「ICS3.5/3.6 ソフトウェアマニュアル」第 2.4 版を自分で読んで確かめたこと（11/7、公式 PDF を pdftotext で取り出した）**

- プロテクション（p.5）: 「プロテクション動作開始までの時間を設定します。…ロックした場合の保護機能です。起動後はサーボのパワーを自動的に50％ダウンさせます。復帰後は、ロックなどを解消した時点で自動的に行われます。」
  設定範囲 10〜255、1 あたり約 0.1 秒。スピードが 127 のときだけ有効。**EEPROM の表（p.23）の出荷時値例は 250（約 25 秒）**。出荷時のままなら、8 秒の起き上がりの間には働かない。
- 電流制限（p.6）: 超えると脱力し、下回ると復帰。目安 1 = 0.1 A（10 = 1.0 A、20 = 2.0 A）。出荷時値例 63（約 6.3 A）。温度制限: 30 = 100 ℃、60 = 80 ℃、87 = 60 ℃（目安）。出荷時値例 80（約 66 ℃）。
- EEPROM の 64 バイト（p.23〜24）: 1 バイトに 4 bit ずつ、奇数番目が上位。ストレッチゲイン（3〜4、出荷時 60 = ストレッチ 30）、スピード（5〜6、127）、パンチ（7〜8、1）、
  デッドバンド（9〜10、2）、ダンピング（11〜12、40）、セイフタイマー = プロテクション（13〜14、250）、フラグ（15〜16）、パルスの上限・下限、通信速度、温度制限（29〜30、80）、
  電流制限（31〜32、63）、レスポンス（51〜52、3）、ユーザーオフセット、ID。`real/servo_tel.py` の `decode_eeprom()` がこの表で読む。
- 読み出しの電流値（サブコマンド 0x03）・温度値（0x04）の単位は書かれていない。電圧を読むコマンドは無い。

**本研究の現状と照らした読み（私の読み、11/7）**

- 実機の弱さの候補は 3 つになった: (a) 電源の電流の合計、(b) サーボのプロテクション（ロックが続くと出力 50 %）、(c) サーボの硬さ（ストレッチ）。
  ただし (b) は、セイフタイマーが出荷時の 250（約 25 秒）のままなら 8 秒の起き上がりでは働かない（実機の値は khr-getup.5 で読む）。
  11/6 夜の照らし合わせ（胸を上げる最初の 2 秒は強く、肩を回す後半だけ弱い）は (a) と (b) のどちらとも合う。(c) だけ（kp を下げる）は合わなかった。
- (b) は時間で弱くなる模型なので、シミュで実機の 4 回と照らし合わせて (a) と比べられる（実機なしでできる）。(a) と (b) の決着は、実機で電源の電流・電圧とサーボの電流を同時に取る。
- 強さの DR を 0.3 倍まで広げるのは先行研究に例がない。幅は測ってから決める（Xie ら）。
- 立って止まったあとの電流には、機械の仕事率の罰（−τ·q̇）は効かない。トルクの 2 乗の罰か、行動の変化の罰か、L2C2 が合う。

**コードで確かめたこと（11/7）**

- Meridian_LITE のファームはサーボに `setPos` と `setFree` しか送らない（`src/mrd_module/sv_ics.h`）。ストレッチ・スピード・電流制限は書き換えず、各サーボの EEPROM の値のまま動いている。
- 同じファームの `lib/IcsClass_V210` に `getStrc`・`getSpd`・`getCur`（電流値）・`getTmp`（温度）がある。近藤の設定ソフトがなくても、ファームのパッチで肩・肘の電流と温度、全サーボのストレッチとスピードを読める
  （計画書の FW-T。フレーム周期への影響は実機で測る）。パンチ・プロテクション・電流制限の値を読む関数は無い（EEPROM の読み出しのコマンドを自分で送るか、近藤の ICS の USB アダプターと設定ソフトを使う）。
