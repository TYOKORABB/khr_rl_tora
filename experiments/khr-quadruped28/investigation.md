# khr-quadruped28 (v28) 事前調査記録 — 報酬を 27 → 18 項目に整理する

- 記録日: 2026-10-04
- 位置づけ: 中間発表後の指摘「**足して足してを繰り返したが、本当に効いているのか確かめられて
  いないのではないか。seed による誤差なのか、どの seed でも効く報酬なのか**」に答えるための版。
- 環境コードの変更なし（`khr_quad_env19.py` を流用）。**設定のみ**。
- 学習スクリプト: `khr_train_quad28.py`

## 1. 動機

v27 時点の有効な報酬は **27 項目**。しかし ablation 済みは 4 項目だけで、**23 項目が未検証**だった。
「積み上げた」ものの大半が効いているか分からない状態は、卒論の弱点である。

**罠**: 罰項は効いているほど自分の値がゼロに近づくため（`heading_error` は v24 の寄与 −0.3085 →
v25 −0.0352 と 1/9 に減ったのに効果は劇的だった）、**寄与の大きさで重要度は判断できない。
除去して学習し直す以外に判定手段がない。**

## 2. 検証の進め方（群検定で GPU 時間を圧縮）

23 項目を個別に leave-one-out × 3 seed だと約 63 時間。段階化した。

| 段 | 内容 | 本数 |
|---|---|---|
| 第1段 | 寄与 0.1 未満の 16 項目を**一括除去** | 2 |
| 第2段 | 機能別 5 群に分割 | 10 |
| 第3段 | 大寄与 7 項目の leave-one-out | 14 |
| 第4段 | **削除可の 9 項目をまとめて除去**（相互作用の確認） | 3 |

**計 27 本を cron で 12:00-18:00 の枠に自動実行**（9/29〜10/04、失敗ゼロ）。

## 3. 削除する 9 項目と根拠

| 群 | 項目 | 根拠（2 seed・個体差あり） |
|---|---|---|
| g5heading | `heading_drift`, `leg_load_balance` | 全指標 2σ 以内。`heading_drift` は v24 で「率を罰しても効かない」と判明した旧実装で `heading_error` と冗長。`leg_load_balance` は v21 で強めたら対称性が悪化した項目 |
| g3jointreg | `similar_to_default`, `hip_pos`, `dof_pos_error` | 悪化指標なし。v7〜v9 当時は飽和解消に効いたが、現構成では `torque_limits` が同じ役目を担う |
| g4gaittime | `gait_swing`, `feet_air_time`, `contact_no_vel` | 全指標 2σ 以内 |
| 単項目 | `acceleration` | 悪化なし。寄与 −1.03 と 4 番目に大きいのに効いていない（scale −4e−05 が極小で実質オフセット） |

## 4. 残す 18 項目のうち、必須と実証されたもの

| 報酬 | 外すとどうなるか |
|---|---|
| `feet_orientation` | **着地時の足裏傾き 4.41 → 34.33°（30.3σ）**。足裏が崩壊し「足の縁で歩く」状態に逆戻り |
| `torque_limits` | 90%超の延べ時間 0.00 → 11.17 %、99%点 59.7 → 100 % |
| `knee_swing_flexion` | 膝 ROM 33.9 → 6.6°（棒脚に戻る） |
| `feet_clearance`（相対量であること） | 前脚の足上げ −22 %（4.8σ） |
| `tracking_lin_vel` | 前進速度 22.0σ 悪化（歩かなくなる） |
| `drift` | トルク平均 2.2σ 悪化 |
| g1smooth 4 項目 | トルク平均 2.2σ 悪化 |
| g2posture 4 項目 | トルク 99%点 63.0 %（2σ 超） |
| `heading_error` | v24→v25 の対照実験で横ずれ 12.18 → 2.88 % |

## 5. 設計判断: なぜ「削除」ではなく `scale = 0.0` か

`reward_scales` から項目ごと削除しても報酬の値は同じ（0 寄与）だが、**GPU の演算順が変わり、
接触物理のカオス性で方策がわずかに変わる**（`measurement_caveats.md` §2 で実測）。
**既に 3 seed で検証済みのチェックポイントをそのまま v28 として使う**ため、
`combo9` と完全に同一の設定を保つ。

- **機械検証済み**: `khr_train_quad28.py` と `khr_train_quad28_combo9.py` の設定差分は **0 件**。
  v27 との差分は **9 件・すべて 0.0**。有効な報酬項は **18**。
- したがって `khr-quadruped28-combo9-s1/s2/s3` が **v28 のチェックポイント**である。

## 6. 合否指標

| 指標 | 目標 |
|---|---|
| トルク平均・99%点・90%超 | v27 と同等（ノイズ床 2σ 以内） |
| 横ずれ率・前進速度 | v27 と同等以上 |
| 膝 ROM・足裏傾き・歩容一致率 | v27 と同等 |
| 転倒（外乱あり） | 0 を維持 |

> **反証可能性**: 個別に影響が無くても、同時に外すと相互作用で崩れる可能性がある。
> どれか 1 つでも 2σ を超えて悪化したら、群を分割して原因を特定する。
