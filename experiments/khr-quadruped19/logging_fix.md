# 実機ログが保存できなかった問題の調査と改修（2026-08-10）

- 対象: `Meridian_consoleS/Meridian_consoleS_quad.py`（四足版コンソール、PC側）
- 症状: 実機動作中に **[Save Log] ボタンを押すとエラー**が出てログが保存できない。
  そのため v19 の実機走行（2026-08-10、動画3本）で**実行ログが1本も残らなかった**。

## 1. 調査結果: 原因は4つ、いずれもPC側 Python の問題

### ① 直接原因: `logs/` ディレクトリが存在しない

`save_log_file()` は**相対パス**で直接 open していた。

```python
logfile_name = 'logs/log.csv'
f = open(logfile_name, 'w', newline='')   # ← ここで例外
```

同一処理を再現して確認したエラー:

```
FileNotFoundError: [Errno 2] No such file or directory: 'logs/log.csv'
```

**なぜ存在しないのか**: `Meridian_consoleS/.gitignore` の2行目に `logs` が指定されており、
**git clone してもこのディレクトリは作られない**。先輩の環境には手動で存在していたが、
本環境（clone 後）には無い、という状態だった。

### ② 保持時間がわずか10秒

ログは `maxlen` 付き `deque`（リングバッファ）で、`MAX_LOG_SIZE = 1000`。
制御周期は `TAU_cycle = 0.01`（100Hz）なので **1000 ÷ 100Hz = 10秒**しか保持できない。
①を直しても、60秒の走行では**最後の10秒しか残らなかった**。

### ③ 毎回 `log.csv` を上書き

固定ファイル名のため、走行ごとにログが消える。

### ④ `f.close()` が無い

ファイルハンドルを閉じておらず、書き込みが確定しない可能性があった。

### 補足1: PlatformIO は無関係
PlatformIO は **ESP32 ファームのビルド・書き込み専用**。CSV 書き出しは PC 側 Python が
単独で行っており、両者に依存関係はない。

### 補足2: `obs2csv` ボタンは未実装
`flag_obs_csv` は定義とセットのみで、**それを読んで書き出す処理が存在しない**（押しても何も起きない）。
※ 以前「obs2csv で実機観測を取得できる」と案内したが誤りだったため訂正する。
　 ただし後述のとおり **log.csv だけで Sim2Real 分析に必要な項目は揃う**ため、実装は不要。

### 補足3: ①②③④は元の二足版にも同じく存在
`Meridian_consoleS.py` にも同じ実装がある（上流からの継承であり、四足版コピーで
持ち込んだ不具合ではない）。今回は実際に使用する四足版のみ修正した。

## 2. 実施した改修（4点）

| # | 改修 | 内容 |
|---|---|---|
| ① | **保存先の自動生成＋絶対パス化** | `os.path.dirname(os.path.abspath(__file__))/logs` を `os.makedirs(..., exist_ok=True)` で作成。clone 直後でも動き、実行ディレクトリにも依存しない |
| ② | **バッファ拡大** | `MAX_LOG_SIZE` **1000 → 12000**（100Hz × **120秒**）。メモリ増は約6MB で実用上問題なし |
| ③ | **タイムスタンプ付きファイル名** | `log_YYYYmmdd_HHMMSS.csv`。走行ごとに残り上書きされない |
| ④ | **`f.close()` の追加** | 書き込みを確実に確定。保存件数と相当秒数もコンソールに表示 |

あわせて `Meridian_consoleS/logs/` を作成済み。

### 動作検証（GUI なしで保存処理を再現）
120秒分（12000サンプル）のダミーデータで `save_log_file()` と同一処理を実行し、
**5.6MB / 12001行（ヘッダ含む）/ 62列** の CSV が正常に生成されることを確認した。

## 3. ログの内容 — Sim2Real 分析に必要な項目は揃っている

| 列 | 内容 | 分析での用途 |
|---|---|---|
| `q1..q22` | 実測関節角[deg] | 観測 `dof_pos`。差分から `dof_vel` も算出可 |
| `qd1..qd22` | 指令関節角[deg] | ポリシー出力 `action` の検証（PD追従の実機版） |
| `gyro_x/y/z` | ジャイロ | 観測 `base_ang_vel` |
| `roll/pitch/yaw` | 姿勢角 | 観測 `projected_gravity` の再構成 |
| `acc_x/y/z` | 加速度 | 参考（衝撃・接地の検出） |
| `Tcycle`, `board_frame`, `pc_frame`, `tau_udp`, `tau_avg`, `esp32_time*` | 周期・通信 | 通信品質、フレーム落ち、遅延の検証 |

**→ `obs2csv` を実装しなくても、[Save Log] だけで Sim-Real ギャップを定量化できる。**

## 4. 次回の実機セッションでの手順

1. コンソールを起動し、通常どおり実機を歩かせる（**120秒以内**なら全区間が残る）。
2. 走行が終わったら **[Save Log]** を押す
   → `Meridian_consoleS/logs/log_YYYYmmdd_HHMMSS.csv` が生成される
   → コンソールに `Saved: ...` と保存件数・相当秒数が表示される（成否がその場で分かる）。
3. 指令の方向（前進/後退/横/旋回）を変えるたびに Save Log を押せば、方向別に分けて残せる。
4. 取得後、シミュ（同一 ckpt・同一コマンド）の観測と重ねて **Sim-Real ギャップを定量化**する。

> 注意: 走行が120秒を超えると、古い分からリングバッファで捨てられる。
> 長時間走らせる場合は途中でも Save Log を押すか、`MAX_LOG_SIZE` を更に増やす。
