# khr-quadruped19 (v19) 事前調査記録 — 前進追従の回復（速度不足を実際に痛くする）

- 記録日: 2026-08-01
- 位置づけ: v18 で「足裏全面接地」を達成した一方、最大の残課題である**前進追従 57%**を回復する。
  方針は [[project_roadmap]]。

## 1. 前提: v18 の到達点と残課題

**維持したい成果**
- **足裏全面接地**: 後脚 足裏傾き（接地時平均）21.4° → **6.1°**（過去最良。ユーザ要望）
- 膝の周期運動を維持（ROM 38.5/47.5°、膝が主動力 32/39% ≥ 足首 31/30%）
- トルク: ピーク 91% → **81%**、定格90%超 **0/22**、duty **0/22**
- 左右対称性 0.8pt・歩容一致率 92/92%・後脚クリアランス 0.019/0.017m（いずれも過去最良）

**残課題**
- **前進追従 57%（実測 0.171 m/s）**。v16 の 75% から戻らない。後退も 51%。

## 2. 診断: なぜ遅いままなのか

**物理的な限界ではない。** v18 のトルクは 平均18% / ピーク81% / duty 0/22 で余裕がある。

原因は**追従報酬の形状**にある。`tracking_lin_vel` は `exp(-err²/sigma)`（sigma=0.15）で、
指令 0.3 に対し実測 0.171（**43%不足**）でも

```
exp(-(0.3-0.171)² / 0.15) = exp(-0.111) = 0.895
```

**最大報酬の 89.5% を獲得できてしまう。** 速度が大きく足りなくてもほとんど損をしない一方、
速く動けば `action_rate` / `dof_vel` / `acceleration` / `torque_limits` のコストが増える。
結果、**遅いままが最適解**になっていた。

これは **v2 で経験した「静止でも前進追従報酬の 94% が得られる」構造と同じ**である。
当時は v3 で「tracking の scale を上げ、動作系の罰を下げる」ことで解決した。

## 3. v19 の対策（環境は khr_quad_env15 を流用 / 学習 khr_train_quad19）

**環境コードは変更せず設定値のみ**のため、env と record は v18 のもの
（`khr_quad_env15.py` / `khr_quad_record15.py`）をそのまま使う（v3/v4 と同じ方針）。

1つの意図＝「**速さの限界価値を上げる**」を、同一報酬項の2つのパラメータで実現する。

| 変更 | 内容 |
|---|---|
| `tracking_sigma` **0.15 → 0.08** | 速度不足を実際に痛くする（43%不足時の報酬 0.895 → 0.812） |
| `tracking_lin_vel` **4.0 → 5.0** | 追従の価値そのものを底上げ |

**効果の見積り（速度に対する報酬の勾配＝限界価値）**

```
v18: 4.0 * exp(-0.129²/0.15) * 2*0.129/0.15 =  6.16
v19: 5.0 * exp(-0.129²/0.08) * 2*0.129/0.08 = 13.10   → 約 2.13 倍
```

**据え置き（v18 の成果を壊さないため）**: `feet_orientation` -3.0 と着地直前の水平要求
（足裏全面接地）、`knee_swing_flexion` 1.8、脚別クリアランス目標（前0.012/後0.02）、
トルク安全策（`torque_limits` -5.0 / `dof_pos_error` -1.0）、`base_height` -3.0、
`leg_load_balance`、`heading_drift`、`feet_air_time`。

### 補足: `tracking_sigma` は旋回にも共用
`_reward_tracking_ang_vel` も同じ sigma を使うが、旋回は既に 103/102%（誤差ほぼ 0）なので
縮小の影響はほとんど受けない。横移動（62%、誤差0.057）も報酬 0.979 → 0.947 と軽微。

### 事前スモークテスト（学習前・num_envs=4）
- `tracking_sigma = 0.08` / `tracking_lin_vel = 5.0` を反映。全26報酬のメソッド対応 OK、報酬 finite。
- **限界価値の増加を検算**: 6.16 → 13.10（**2.13倍**）。

## 4. リスクと監視項目

- **v2 の教訓**: 「sigma を厳しくしただけでは かえって遅くなった」。当時は動作系の罰が大きかった
  （`action_rate` -0.05, `similar_to_default` -0.1）が、現在は -0.02 と小さく条件が異なる。
  それでも**遅くなる可能性**は残るため実測で確認する。
- **トルクのピーク**（最重要）: 速く歩けば上がる。v18 で 81%。「100%は絶対NG」の要件があるため
  **90%を超えないか**を最優先で監視し、超えたら次版で `knee_swing_flexion` か tracking を戻す。
- **足裏傾き 6.1°**（ユーザ要望の成果）が悪化しないか。

### v19 の合否指標（v18比）
- **前進追従の回復（主目的）**: 57% → v16 水準（75%前後）へ。実測速度 0.171 → 0.22 m/s 以上。
- **トルクのピーク（必須）**: 81% → 90% を超えないこと。duty 0/22 を維持。
- **足裏傾きの維持（必須）**: 6.1° を大きく悪化させないこと（10° 以内が目安）。
- 膝 ROM が潰れないこと（38.5/47.5° 前後を維持）。
- 横・旋回・左右対称性・クリアランスが崩れないこと。
