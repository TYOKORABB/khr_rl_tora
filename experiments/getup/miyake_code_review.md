## こちらの研究にとって分かったこと

1. **v2 の候補 1（行動の平均を ±1 に収める）に直接の前例がある。** 三宅さんの設定は、エントロピーの項を 0 にし、平均が ±1 付近を超えた分を損失に足していた（rl_games の bound loss。zip 内の AMP 用の同じ関数は境界 1.0）。
   getup-v1 では、平均が 9 割の時間 ±1 の外にあり、エントロピーの項で std が 0.30 → 0.92 と増え続けた（`getup/DIARY.md`）。同じ対策がそのまま候補になる。
   rsl-rl 5.4 には同じ項が無いので、入れるなら PPO の損失に足すか、報酬の罰で近似する。
2. **トルクの飽和は三宅さんの設定のほうがずっと強い。** 剛性 85・上限 1.2753 N·m では、目標とのずれ 0.015 rad（0.9°）で上限に張り付く（本研究は 0.055 rad）。
   シミュの録画では跳ねるように立っており、実機で「腕で胴体を起こす局面」で失敗したこと（論文）と整合する。v2 の候補 2（目標角を測った角度の近くに制限する）と、
   計画書 §5.3 の持ち上げ試験 E2a（実機のトルクの予算を先に測る）の必要性を裏づける。
3. **初期状態が 1 つで、個体差もない。** 学習した動きは 1 本の軌跡に寄りやすく、実機の初期姿勢の違いに弱い。初期状態のデータと個体差を入れた本研究の方針（§4.3.1・§4.6）は、この点への対策になっている。
4. **観測に関節角が無く、足と前腕の向き・胴体の四元数（ヨーを含む）が入っている。** 開ループの再生には問題ないが、閉ループで実機に載せるには観測を作り直す必要がある。
   本研究は実機で得られる量だけで観測を作っている（§4.3.3）。
5. **報酬を 0 未満で切っているので、終了時の −1 は効いていない**（死んでも 0 になるだけで、以後の報酬を失うことが罰になる）。
6. 仰向け版 `khr3_from_back.py` では、直立としゃがみの姿勢の報酬で、正規化した行動と rad の関節角を直接比べている（呼び出しで渡す値の取り違え）。
   単位が合っていない可能性が高い。仰向けは本研究では L4（COULD）なので、比べるときに注意する程度。
7. URDF: 学習用の `_test` は effort を 1.373 → 1.2753 N·m（93 %）に下げてある。股関節ピッチの上限は +30°（本研究の URDF は +100°）、股関節ロールは外側だけ。
   質量は 1.6 kg で同じ。
