# getup-v8（段階 L4）— 計画と判定の基準（学習の前に固定、2026-11-04）

## 0. きっかけ

ユーザーの決定（11/4）:「L3を終え、L4に進もう。」

## 1. 今の状態と L4 の役割

- 歩行中に転ぶと、止まった状態の 97.6〜99.0 % は胸が上の範囲（u0 < 0）である（`experiments/getup/falls/falls.md`）。
- v7 の B は、段階に入れていない胸が上の状態からも起き上がるが、シードで割れる（`experiments/getup/v7_results.md`）。

| 最初の状態 | シード 1 | シード 2 | シード 3 |
|---|---|---|---|
| 歩行中に転んだ状態の全部（`falls_all`、229 状態） | 28.0 | 93.9 | 98.7 |
| 主のバンクの胸が上の状態（1,823 状態） | 31.4 | 90.9 | 98.6 |

- シード 1 は、L3 の段階で最後に立っている割合が 1500 から 2999 イテレーションまで 0.78〜0.80 で止まった。
- したがって L4 の役割は、仰向けを一から覚えさせることではなく、**どのシードでも解けるようにすること**である。そのために、胸が上の状態と脱力の状態を学習で直接見せる。

## 2. 構成（1 通り × 3 シード、3 試行）

土台は v7 の B（hard ＋ flipthr）。キュー `getup/jobs/queue_v8.txt`、全体の手順 `getup/jobs/run_v8.sh`、学習 `getup/train_getup8.py`。名前は `getup8-L4-s{1,2,3}`。v7 の B との差は次の 3 つだけである。

| 変更 | 内容 |
|---|---|
| 段階 L4 を足す | L4 = 主のバンクの全部 ＋ 歩行中に転んだ状態（F）の全部。学習用 16,942 状態、評価用 4,204 状態 |
| 苦手な状態を多く選ぶ | L4 の段階のリセットの半分を、脱力で u0 < 0.5 の学習用 4,601 状態から選ぶ。内訳は胸が上 3,377（F を含む）、横倒しの範囲 1,224。F は全部で 913 |
| イテレーション | 3000 → 4000。v7 の B が L3 に上がったのは 894〜1457。L4 に上がってから学ぶ分を足す |

- 苦手な状態は、最初の状態の特徴（脱力・u0）だけで決める。評価用の状態や評価の結果は使わない。

- 3 つを同時に変えるので、どれが効いたかは分けられない。

## 3. 判定の基準（学習の前に固定）

主な指標 F は、**歩行中に転んだ状態の全部の成功率**（`eval_getup` の `falls_all`、ドメインランダム化あり、8 秒、評価用の 229 状態）。v7 の B は 28.0・93.9・98.7 %（平均 73.5 %）。

合格は、次のすべてを満たすこと。

| 種類 | 条件 | v7 の B |
|---|---|---|
| 主な指標 | F が 3 シードの平均で 85 % 以上 | 73.5 |
| どのシードでも解ける | F が 3 シードとも 70 % 以上 | 最低 28.0 |
| 段階の基準 | L4 の成功が 3 シードの平均で 80 % 以上（計画書 `docs/GetUpSim2RealPlan.md` の getup-L4 の基準） | — |
| 悪くしない 1 | L3 の成功が 3 シードの平均で 80 % 以上 | 91.3 |
| 悪くしない 2 | L2 の成功が 3 シードの平均で 85 % 以上 | 92.3 |
| 悪くしない 3 | u0 ≥ 0.5 の脱力の状態の成功が 3 シードの平均で 85 % 以上（実機に近い条件） | 92.5 |
| 悪くしない 4 | 脱力の横倒しの範囲 M が 3 シードの平均で 70 % 以上 | 82.2 |
| 悪くしない 5 | L4 でトルクが上限に張り付く時間が 3 シードとも 1 % 未満 | L3 で最大 0.095 |

- 85 % と 70 % に理論の根拠はない。v7 の B でよく解けた 2 シードが 94〜99 % なので、シード 1 のような停滞がなくなれば平均は 85 % を超える、という線に置いた。70 % は B の最低（28.0 %）を大きく超える線である。
- M の 70 % は、L4 の段階で脱力の横倒しの練習が減る（39.9 % → 14.0 %）ので、B より多少下がることを許す線である。
- 3 シードがそろうまで判定しない。
- 判定を受けて何をするかは、ユーザーが決める。提案は次のとおり。
  - 合格: シミュレーションの起き上がりは L4 まで完了とし、この版を土台に実機か卒論の記述へ進む。
  - 不合格: 失敗の型を見て、シードの追加、イテレーションの追加、状態の選び方の変更を相談する。
- 参考（判定には使わない）:
  - `eval_getup --states falls`・`--states chest_up`（v7 の B と同じ測り方）、u0 の区間別、脱力か保持か
  - 失敗の型の割合（`failure_modes`）
  - トルクの 99 % 点、成功までの時間、立った後の揺れ（`hold_analysis`）、昇格のイテレーション、学習中に最後に立っている割合
- 動画: 検証のたびに撮る。`eval_getup` の段階ごと（L0〜L4）に加えて、脱力の横倒し（`*_limpside_L3.mp4`）、転んだ状態（`*_falls.mp4`）、胸が上の状態（`*_chest_up.mp4`）。

## 4. 事前の見立て（外れたらそれも記録する）

- L4 に上がるのは 1200〜2200 イテレーション。
- F の平均は 85〜95 %、最低のシードは 60〜90 %。胸が上の脱力をリセットの約 33 % で見るので、シード 1 のような停滞は減るとみる。
- L4 の平均は 82〜92 %。L2 は 88〜93 %、M は 70〜90 %（練習が減るので B より下がるかもしれない）。
- 上限に張り付く時間は 0.1〜0.3 %。胸が上から寝返る時間が増えるので B より少し長いが、1 % には届かない。

## 5. GPU と自動実行

- whisper と重ねない（`gpu_gate.sh`、1 本に 120 分の空きが要る）。実測の見込みは学習 71 分（v7 の 56 イテレーション/分）、段階の検証 15 分、追加の検証 9 分で、1 シード約 96 分、全体で約 5 時間。
- 実機の実験の間は止める。
- 検証の道具の変更: L4 の評価用 4,204 状態を一度に動かすため、`eval_getup` の体の数の上限 4096 を外した（L3 までは 4096 未満なので同じ）。動作確認用に `eval_getup`・`failure_modes` に `--cpu` を足し、`failure_modes` の集計に胸が上の範囲と F の行を足した（L3 までの記録では行が増えない）。

## 6. 変更の記録

基準と構成は変えていない。

11/4 の 1:56 に、本人の許可（「今回に限りいったんWhisperを止めていいよ。でもちゃんと明日以降再開するようにしてね。なるべく早くやってほしい。」）を受けて whisper を止め、学習を前倒しした。ジョブが終わると自動で whisper の cron を元に戻す。学習の条件は変わらない。今回限りの扱いで、§5 の「whisper と重ねない」はそのまま。

結果を見てから、判定に使わない参考の測定を足した（11/4）。v8 が B より低かったので、L4 の学習で悪くなったのか、もともとできていなかったのかを分けるため。

- `eval_getup --ckpt <番号> --states falls`: v8 は L4 に上がる直前（1800・1700・800）、v7 の B のシード 2・3 は L3 に上がってすぐと約 500 イテレーション後（1700・2000、1500・1800）。結果は `v8_results.md` の最後の節。
