# 目標角の張りつきの調べ（2026-11-21、論文には入れない）

本人（11/21）:「張り付きを調べた後に段階１の案を作ってください。」
段階 0b の本命は、比例ゲイン 7 の前進で v31 より速かった（0.182 対 0.114 m/s）。ただし目標角が 9 割の周期で速さの制限（0.06 rad/周期）に、8 割でずれの上限（測った角度 ± 0.08 rad）に当たっていた。これが何なのかを、学習せずに今ある方策で調べた。

- 道具: `unified/tools/analyze_saturation.py`（条件は `unified.eval_walk` と同じ: 128 体・12 秒・先頭 2 秒を捨てる・前進 0.3 m/s・個体差は 0 点のずれだけ・乱数の種 0）。記録 `analysis.json`。
- v31 には制限がないので、「v31 が同じ制限の下にあったら当たるか」を測った（送った目標角の 1 周期の変化と、その周期の前に測った角度との差）。

関節ごと（比例ゲイン 7、本命 3 シードの平均で速さの制限を超える割合）: どの関節も 79〜99 %。歩行に関係しない首の回転 89 %・腰の回転 99 %・肘の回転 90 % も張りつく。v31 がずれの上限を超えるのは肩・股関節・膝のピッチ（33〜57 %）だけで、ほかの関節は 0〜9 %。

## 2. 分かったこと

- **張りつきは弱いサーボのせいではない**。v31 を同じ比例ゲイン 7 で動かすと、目標角の 1 周期の変化は 0.06 を一度も超えず（99 % 点 0.04 rad）、ずれの上限 0.08 を超えるのは 11〜15 %（体重を支える肩・股関節・膝のピッチだけ）。
- 段階 0b の方策は、制限の 5〜6 倍（中央値 0.3 rad、99 % 点 1.5〜2 rad）の目標角の跳びを毎周期出し、制限がそれを削っている。行動はほぼ毎周期大きく振れている（|行動| の中央値 0.8）。歩行に関係しない関節まで張りつくので、力を出すための振り方ではなく、罰がないので出ている「ばたつき」と考えられる。
- 罰に見えていない理由: unified_env0 の行動の変化の罰 2 項は「送った目標角（制限のあと）」の変化で測るので、1 周期の変化は 0.06 で頭打ちになり、0.06 を超える跳びは罰に入らない。計画（`../stage0_plan.md` §2）では「行動の変化の罰は v31 と同じ物理量」としたが、制限のあとで測ったので、v31 の罰（行動そのものの変化）と同じではなかった。

## 3. 次の 1 つの変更（案、基準は本人と決める）

- `unified/envs/unified_env0r.py`: 行動の変化の罰 2 項を **制限の前の目標角**（q_raw = 公称 + s × 行動）の 1 階差分・2 階差分で測る（÷ 0.15 rad、重みは v31 と同じ −0.02・−0.01）。ほかは段階 0b と同じ。
- 本命と同じシード 1〜3・硬さ 4〜9・4000 イテレーション。比べる相手は段階 0b の本命（unified0b-kplow-s1〜3、同じシード）。

## 4. 判定の基準（結果の前に固定、11/21 本人が「10 % 以下＋v31 より速い」を選んだ）

選ばなかった案: 「10 % 以下＋転倒 0 だけ（速さは v31 を下回ってもよい）」、「半分以下（45 % 以下）＋v31 より速い」。

- 主の量: 比例ゲイン 7 の前進 0.3 m/s で、速さの制限に当たる割合（`unified.eval_walk` の rate_bind_pct、関節 × 周期）。段階 0b の本命は 3 シード平均 91.3 %。
- **合格**: unified0r の本命 3 シードの平均が 10 % 以下、かつ段階 0 と同じ速さの基準（比例ゲイン 7 の前進の速さの平均が v31 の平均 0.114 m/s を 2σ より大きく上回る（σ = max(v31 の 3 シードの標準偏差, unified0r の 3 シードの標準偏差)）、3 シードすべてが v31 の平均より上、前進の転倒が 3 シードとも 0）。
- 合格なら段階 1 はこの罰（制限の前の目標角で測る）で作る。合格しないときは、どちらの条件で落ちたかを書き、段階 1 の案と一緒に本人と決める。
- 1 シードの値で結論を書かない。
- 待ち行列 `unified/jobs/run_stage0r.sh`（11/21 開始、3 本で約 5 時間半）。

## 5. 0r は崩れたので止めた → 方策の平均だけを罰する 0c（11/21）

- 0r（罰を制限の前の目標角で測る、`unified/envs/unified_env0r.py`）のシード 1 は、700 イテレーションで学習中の転倒で終わる割合 0.99・報酬 9（段階 0b は同じ時点で 0.22・91）。行動の平均が ±1 の外にある割合は 0.87（段階 0b は 0.27）。
- 原因: std 0.5 の探索のゆらぎは目標角で約 0.5 rad（s は最大 1.2 rad）。v31 は学習の最後で std 0.14 × 0.15 = 約 0.02 rad なので、約 25 倍。報酬の罰は実際に送った（ゆらぎを含む）行動で測るので、ゆらぎそのものが大きな罰になり、方策は平均を ±1 の外に張りつけて（切られてゆらぎが消える）逃げた。段階 0b の張りつきも、元をたどればこの大きすぎるゆらぎと、それを削る制限の組み合わせと考えられる。
- 本人の決定（11/21）:「止めて平均だけ罰する（勧め）」。0r の待ち行列は 18:31 ごろにシード 1 の途中（約 900 イテレーション）で止めた（logs/unified0r-kplow-s1 は途中まで、判定に使わない）。
- **0c**（`unified/ppo_caps.py`、学習の設定 `--caps 0.1`）: 環境と報酬は段階 0b のまま。PPO の損失に、方策の平均（決定的な出力）の目標角が続く 2 周期で変わる分の 2 乗（÷ 速さの制限 0.06 rad、関節と組で平均）を係数 0.1 で足す（CAPS の時間の項、Mysore ら 2021）。探索のゆらぎは入らない。std 0.5 は変えない（段階 1 の起き上がりの探索も変えない）。
  - 係数 0.1 の決め方: 損失の値 1 が「平均の目標角が毎周期ちょうど制限 0.06 rad 動く」に当たる。段階 0b の跳び（中央値 0.3 rad）なら 25 × 0.1 = 2.5 で、PPO の損失より大きく効く。v31 なみ（0.01 rad）なら 0.03 × 0.1 = 0.003 でほぼ効かない。
- 判定の基準は §4 のまま（本人が選んだ「10 % 以下＋v31 より速い」）。比べる相手は段階 0b の本命。待ち行列 `unified/jobs/run_stage0c.sh`（3 本で約 5 時間半）。
