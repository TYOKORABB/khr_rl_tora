## 2. v15 の仮説（本命）: 足裏水平罰が遊脚中も効いている

`_reward_feet_orientation`（−1.0, v7 導入）の実装を精査したところ、
**接地/遊脚を区別する contact マスクが無く、常に後脚の足裏を水平に保つよう罰していた**。

```python
# v7〜v14 の実装（抜粋）: 接地判定なしで常時ペナルティ
for f in range(len(self.rear_feet_indices)):
    v = transform_by_quat(up, quat[:, f, :])
    pen = pen + torch.sum(torch.square(v[:, :2]), dim=1)   # ← swing 中も罰される
```

この設計だと:
- **遊脚中に膝を曲げると足裏が傾く → 罰される → 膝の屈曲が抑制される**。
- 足裏を水平に保つ仕事が **足首に集中** する。
- ⇒ 「足首が最大トルク・膝は不使用（棒脚）」という実測を最も自然に説明できる。
- 導入時期（v7）とも整合する。膝 ROM は v8 の 22.3° を最後に、v9 以降で半減している。

## 3. v15 の対策（環境 khr_quad_env12 / 学習 khr_train_quad15）

**変更は1点のみ**（ablation を明確化するため）。

| 変更 | 内容 |
|---|---|
| `_reward_feet_orientation` を **接地時のみ** 適用 | `feet_orientation_stance_only: True`。遊脚中は足裏の傾きを許し、膝・足首を自由に振れるようにする。接地時は従来どおり水平を促すため、v7 で解決した「足の縁で歩く」問題（接地の質）は維持する狙い |

据え置き: 脚別クリアランス目標（前0.012 / 後0.02）、`base_height` −3.0、`torque_limits` −5.0、
`dof_pos_error` −1.0、`leg_load_balance`、`heading_drift`、`feet_air_time`、姿勢・トロット。

### 事前スモークテスト（学習前・num_envs=4）
- `feet_orientation_stance_only = True` 反映、全25報酬のメソッド対応 OK、報酬 finite。
- **マスクが実際に効いていることを確認**: 同一状態で 接地限定ON = 0.0000 / 従来(常時) = 0.0671
  （その瞬間の後脚接地率 0%）。ON ≤ OFF を assert で検証。

## 4. 学習と検証（このあと）
```bash
python khr_train_quad15.py -e khr-quadruped15 -B 4096 -I 4000 --seed 1
python khr_quad_report.py -e khr-quadruped15
```
### v15 の合否指標（v14比）
- **膝 ROM の回復（主目的）**: 6.4〜14.8° → 増加（v8 の 22.3° が一つの目安）。
- **足首と膝の役割の是正**: ankle_pitch の負荷が knee を上回る状態の解消。
- **ブレーキ時間の低下**: 73〜87% → 低下（駆動的な力の使い方へ）。
- **後脚クリアランスの増加**: 0.007〜0.008m → 目標 0.02m へ。
- **接地の質を落とさないこと（副作用チェック）**: 後脚の足裏傾き（接地時平均 11.0°）が
  悪化しないこと。悪化するなら v7 の「足の縁で歩く」問題の再発を意味する。
- **トルク安全性の維持（必須）**: 飽和 0/22、ピークが定格80%を超えないこと。
- 追従・直進性・エピソード長が大きく崩れないこと。

> 遊脚中の足裏が自由になるため、着地時の姿勢が乱れて接地の質が落ちるリスクがある。
> 悪化した場合は「接地直前(位相が stance に入る手前)だけ水平を促す」等の中間案を検討する。
