# 是正後の v27・v28 の横移動（2026-10-14）

是正前の v28 の検証（[`../khr-quadruped28/directions.md`](../khr-quadruped28/directions.md)）では、報酬を 27 → 18 項目に減らした v28 で
**横移動が 66 → 77 %** に上がった。是正後の 3 seed では横ずれ・速度の改善が再現しなかった（[`findings.md`](findings.md)）ので、
横移動も是正後の機体で測り直した。

- 方策: `fixurdf-v27-s1〜3`・`fixurdf-v28-s1〜3`（URDF の可動域を是正した機体で学習し直したもの、ckpt 3999）
- 測定: `quad/eval_with_urdf_fix.py khr_quad_env19 -n 128 -r 3 --cmd 0 0.15 0`（是正前の v28 の検証と同じ: 128 体・12 秒で先頭 2 秒を捨てる・3 回反復）。
  ジョブ `quad/jobs/measure_strafe_fixurdf.sh`、結果 `../results_json_fixurdf/directions/fixurdf-v{27,28}-s{1,2,3}_strafeL.json`
  （`summarize.py` の集計に混ざらないよう別フォルダ）
- 値: **`with_offset`（サーボの 0 点のずれ＝個体差あり）の `vy_mps`**（横方向の速さ）。是正前の表（0.0995 → 0.1150 m/s）と同じ量で、
  是正前の JSON から計算し直すと平均がちょうど一致する。`speed_mps`（前後のずれも含む速さ）で計算すると数 pt ずれるので使わない。
- 動画: `media/videos/walk_fixurdf-v27_strafe_left.mp4`・`walk_fixurdf-v28_strafe_left.mp4`（seed 1、12 秒、git には入れない）

## 分かったこと

1. **是正後も v28 の横移動は v27 より速い（68 → 75 %、+0.0102 m/s）。** seed ごとの値の範囲が重ならない（v27 の最大 0.1043 < v28 の最小 0.1063）。
   差は seed 間の標準偏差の約 2 倍（3 seed ずつの Welch の t は 2.7）。
2. **ただし伸びは是正前より小さい（+11 pt → +7 pt）。** 是正前の v28 の 77 % は seed 2 の 0.1263 が引き上げていた。
3. したがって v28（報酬の総点検）について言えるのは、「9 項目を外しても劣化しない」に加えて**「横移動は是正後も上がる（+7 pt）」**まで。
   横ずれ・前進の速さの改善は是正後に再現しない（[`findings.md`](findings.md)）ので、「外すと性能が全般に上がる」とは言えない。
4. 前進を詰めた v30・v31 の横移動（69〜70 %）は、是正後の v28（75 %）より低い。v29 以降の変更が横移動を少し下げた可能性がある
   （版をまたいだ比較で、原因は切り分けていない。v30・v31 は URDF ファイルで、fixurdf-v28 は実行時の上書きで是正しており、
   この 2 つはトルク平均もずれている未解決の問題がある＝開発日誌 v2 §4.8）。
5. トルクの 99%点は 4 つとも 51〜53 % で大きな差はなく、転倒は全条件で 0。
