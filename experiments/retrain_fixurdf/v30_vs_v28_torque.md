# v30 と是正後の v28 のトルク平均の差（2026-10-21 の調査）

開発日誌 §4.8 の未解決: v30（URDF ファイルで是正、`khr_quad_env21`）と是正後の v28（元の URDF ＋ 実行時の上書き、`khr_quad_env19` ＋ `quad_compat`）は
同じ「v28 の報酬 + 可動域の是正」のはずなのに、トルク平均（128 体・個体差あり・3 反復）が 3 seed の範囲で重ならない。

| | seed 1 | seed 2 | seed 3 | 平均 ± 標準偏差 |
|---|---|---|---|---|
| v30 | 19.12 % | 19.76 % | 20.09 % | 19.66 ± 0.49 % |
| 是正後の v28 | 18.32 % | 18.54 % | 18.73 % | 18.53 ± 0.21 % |

（ノイズ床 v23 × 4 seed の標準偏差は 0.27 %。差 1.13 pt、Welch の t は約 3.7）

## 確かめたこと（すべて CPU）

| 確かめたこと | 結果 |
|---|---|
| 保存された設定（cfgs.pkl の 5 つ） | 実行の名前（run_name）以外すべて同じ |
| 学習のスクリプト（`khr_train_quad28.py` と `khr_train_quad30.py`、コメントを除く） | 既定の名前と読み込む環境の名前だけが違う |
| 環境のコード（`khr_quad_env19.py` と `khr_quad_env21.py`、コメントを除く） | URDF のファイル名だけが違う。環境は可動域を自分では覚えていない |
| 組み立てた環境の関節の性質（可動域・PD・トルクの上限・アーマチュア・減衰・摩擦・質量） | 同じ |
| 同じ方策（v30-s1）を 16 体・個体差なしで 300 歩、決定的に | 関節角がすべての歩でビット単位で同じ |
| 両方の方策を両方の環境で、凍結した測定の関数（`khr_quad_eval_metrics.measure`、64 体・個体差あり・10 秒） | 値は環境によらずビット単位で同じ（下の表） |

| 方策 | env21（ファイルで是正） | env19 ＋ 実行時の上書き | 当時の GPU の測定（128 体・3 反復） |
|---|---|---|---|
| v30-s1 | 19.10 % | 19.10 % | 19.12 % |
| 是正後の v28-s1 | 18.27 % | 18.27 % | 18.32 % |

## 分かったこと

- **是正のやり方（ファイルか実行時の上書きか）と測り方は、差の原因ではない**。同じ方策は、どちらの環境でも同じ値になる。
- 差は**学習の結果の方策そのもの**にある。設定・コード・環境が同じで seed も同じ（v30-s1 と v28-s1 はどちらも seed 1）なのに方策が違うのは、
  GPU での学習が同じ seed でも再現しないため（接触の計算の並列の順で小さな差が出て、学習の途中で広がる）。
- したがって 2 つの組は「同じ設定の 3 seed ずつ」で、差は seed による学習のばらつきとみるのがいちばん単純な説明。
  v30 の 3 seed の標準偏差（0.49 %）はノイズ床（0.27 %）より大きく、v23 で作ったノイズ床が後の版のばらつきを小さめに見ている可能性がある。
  また v28 と v30 の比較では 12 の指標を見ていて、そのうち 1 つが偶然この程度に離れることは珍しくない。
- 確かめるには、同じ設定の seed を足す（例: v30 と是正後の v28 に 2 seed ずつ、約 6 時間の GPU）。結論（v31 は v30 よりトルクが低い）は v30 との比較なので、この件では変わらない。
