# khr-quadruped14 (v14) 事前調査記録 — 後脚の「変な力の入れ方」の診断と対策

- 記録日: 2026-07-30
- 位置づけ: v13 の残課題（後脚が上がらない・力の入れ方が不自然）への対策。方針は [[project_roadmap]]。
- ユーザ指摘: 「前脚は v12 までの上げ幅でいい。問題は後ろ足で、**変な力の入れ方をして歩いてる感じ**」

## 1. 診断: 後脚の力の入れ方を実測（v13 model_3999, 前進0.3, 8秒）

各関節の可動域(ROM)・平均トルク・**力学的仕事(τ·ω)** を測定。
「ブレーキ時間%」＝ トルクと関節速度が逆符号（＝動きに逆らって力を出している）の時間割合。

| 後脚の関節 | ROM | 平均\|τ\| | 負荷 | ブレーキ時間 |
|---|---|---|---|---|
| l_hip_pitch | 15.2° | 0.381 Nm | 28% | 73% |
| **l_knee_pitch** | **9.6°** | 0.258 Nm | 19% | 78% |
| **l_ankle_pitch** | 14.2° | **0.412 Nm** | **30%** | 80% |
| r_hip_pitch | 13.8° | 0.387 Nm | 28% | 73% |
| **r_knee_pitch** | **10.2°** | 0.325 Nm | 24% | 65% |
| **r_ankle_pitch** | 12.1° | **0.408 Nm** | **30%** | 82% |

### 判明した4つの異常

1. **膝がほとんど曲がっていない（ROM 9.6〜10.2°）**。
   v8 では膝 ROM 22.3° を確保できていた（当時「膝ロック」を解消した成果）。**v9 以降で半減**している。
2. **足首が膝より大きなトルクを負担（30% > 19〜24%）**。
   四足の主動力は本来 膝・股関節。足首が最大負荷＝**脚が棒のまま足首を支点に振られている**、
   機械的に不自然な使い方。これが「変な力の入れ方」の実体と考えられる。
3. **力の 73〜85% が動きに逆らう向き（ブレーキ）**。駆動ではなく抵抗が主。
4. **胴体が上下に 2mm しか動いていない**（base_z std=2.0mm, 全振幅6.5mm, 平均0.199m）。
   `base_height` 罰が **−10.0** と全報酬中で最大級であり、垂直方向がほぼ固定されている。

### 因果の解釈

胴体高さが固定（±2mm）されていると、後脚を持ち上げるには膝を大きく畳むしかない。しかし
v9 で導入した `dof_pos_error`(−1.0)・`torque_limits`(−5.0)、v10 の平滑化罰が
「関節を大きく速く動かすとコスト」として働き、膝の屈曲を抑え込んでいる。
結果、脚は屈曲せず棒のまま振られ、足首が支点として最大トルクを負担する。
**トルク飽和を潰すために入れた制約が、同時に膝の主動力としての役割を奪った**という構図。

補足: v12 では左膝 ROM 4.5° / 右膝 16.9° と左右で使い方が全く異なっていた（v13 で 9.6/10.2 と対称化）。
この非対称も「変な感じ」の一因だった可能性がある。

## 2. v14 の対策（環境 khr_quad_env11 / 学習 khr_train_quad14）

ユーザ選択の方針＝**「胴体の上下動を許す」**。変更を2点に絞り ablation を明確化する。

| 変更 | 内容 |
|---|---|
| **`base_height` −10.0 → −3.0（主対策）** | 胴体の垂直方向の自由度を回復し、後脚が畳める余地を作る。上下動 2mm という異常な固さを緩める |
| **クリアランス目標を脚ごとに分離** | `foot_clearance_target_front = 0.012`（**前脚は v12 水準に戻す**。v13 で 0.032 まで上げたが不要とのユーザ判断）、`foot_clearance_target_rear = 0.02`（問題の後脚のみ引き上げ。v13 実測 0.005m） |

据え置き（安全性の維持のため）: `torque_limits` −5.0 / soft 0.65、`dof_pos_error` −1.0、
`leg_load_balance`、`heading_drift`、`feet_air_time` 1.0、`contact_no_vel` −1.0、姿勢・トロット。

実装: `foot_clearance_target` をスカラから **脚別テンソル [FL, FR, RL, RR]** に変更
（`_reward_feet_clearance` はブロードキャストでそのまま動作）。

### 事前スモークテスト（学習前・num_envs=4）
- `foot_clearance_target = [0.012, 0.012, 0.02, 0.02]`、`base_height = −3.0` 反映。
- 全25報酬のメソッド対応 OK、`foot_ref_z = [0.101, 0.101, 0.027, 0.027]` 取得、報酬 finite。

## 3. 学習と検証（このあと）
```bash
python khr_train_quad14.py -e khr-quadruped14 -B 4096 -I 4000 --seed 1
python khr_quad_report.py -e khr-quadruped14
```
### v14 の合否指標（v13比）
- **後脚クリアランスの増加（主目的）**: 0.005〜0.006m → 0.02m に近づくこと。
- **膝 ROM の回復**: 9.6〜10.2° → 増加（v8 の 22.3° を一つの目安に）。
- **足首と膝の役割の是正**: ankle_pitch の負荷(30%)が knee を上回る状態の解消。
- **ブレーキ時間の低下**: 73〜85% が下がること（駆動的な力の使い方へ）。
- **前脚クリアランスが v12 水準（約0.012m）に戻ること**（上げすぎない）。
- **トルク安全性の維持（必須）**: 飽和 0/22、ピークが定格80%を超えないこと。
- 追従・直進性が大きく崩れないこと。

> 胴体の上下動を許すと `base_height` の拘束が緩む分、姿勢が不安定化するリスクがある。
> 転倒・エピソード長の悪化が出たら −3.0 を −5.0 程度に戻して再調整する。
