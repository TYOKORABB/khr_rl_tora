# ご報告: khr3hv の URDF で `r_hip_pitch` の可動域が左右反転している件

（`s-kajita/khr3hv` の URDF についての報告。2026-10-06 作成）

## 要旨

`khr3hv` の URDF において、**`r_hip_pitch` の可動域が `l_hip_pitch` の鏡像**になっています。
しかし両者は**回転軸が同一**（`axis xyz="0 1 0"`）で、**関節原点の rpy もどちらも `0 0 0`**
（フレームは鏡像ではありません）。そのため可動域を反転させる理由がなく、**誤りと考えられます。**

同梱の全 URDF（`khr3hv.urdf` / `_12dof` / `_19dof` / `_b` / `_c` / `_d` / `_torq10x` /
`_middle_feet` / `_small_feet`）**9 本すべてに同じ記述**があります。

## 該当箇所

`urdf/khr3hv.urdf`

| 行 | 関節 | axis | lower | upper |
|---|---|---|---|---|
| 580 | `l_hip_pitch` | `0 1 0` | **−1.919862177**（−110.0°） | +1.745329252（+100.0°） |
| 657 | `r_hip_pitch` | `0 1 0` | **−1.745329252**（−100.0°） | +1.919862177（+110.0°） |

## 誤りと考える根拠

**(1) 他の pitch 関節はすべて左右同一で、hip_pitch だけが反転している**

| 軸 | 関節 | 左右の可動域 |
|---|---|---|
| roll | `ankle_roll` (−30/+20 ↔ −20/+30)、`hip_roll` (−20/+25 ↔ −25/+20)、`shoulder_roll` (−5/+180 ↔ −180/+5) | **鏡像**（外転/内転の向きを表すので妥当） |
| pitch | `ankle_pitch`、`elbow_pitch`、`knee_pitch`、`shoulder_pitch` | **左右同一** |
| pitch | **`hip_pitch`** | **鏡像** ← ここだけ roll 系と同じ扱いになっている |

**(2) シミュレーション上での実測**

左右の `hip_pitch` に**同じ +0.2 rad** を与えたときの足先変位（Genesis 0.4.6）:

| | 変位 [m] |
|---|---|
| 左足 | (−0.0332, −0.0001, +0.0020) |
| 右足 | (−0.0316, 0.0000, +0.0021) |
| 向きの一致度（正規化内積） | **+1.000** |

**両足が同じ向きに動きます。** フレームが鏡像なら逆向き（内積 −1）になるはずで、
可動域を反転させる根拠がないことを示しています。

**(2-b) 姿勢に依存しない確認（推奨）**

足先変位は測定時の姿勢に依存するため、より直接的な 2 つの確認を併せて示します。

**回転軸をワールド座標で読む**（既定姿勢）:

| 関節 | ワールド軸 |
|---|---|
| `l_hip_pitch` | (+0.00000, **+1.00000**, +0.00000) |
| `r_hip_pitch` | (+0.00000, **+1.00000**, +0.00000) |

正規化内積 **+1.000000**。両軸は完全に同一です。
解析的にも、`base_link → hip_yaw → hip_roll → hip_pitch` の
**3 関節すべての `origin rpy` が `0 0 0`**、`origin xyz` の違いは y の符号＝平行移動のみで、
平行移動は回転軸を反転できません。

**無操作で立たせるだけで左右差が出る**（最も単純な再現）:

行動ゼロで 25 step 置いたときの股関節角（四足の既定角 −101.41°）

| | 左 | 右 | 左右差 |
|---|---|---|---|
| 現状の URDF | −101.37° | **−100.07°** | **1.30°** |
| 右の可動域を左と同じにした場合 | −101.42° | −101.42° | **0.00°** |

既定角 −101.41° が右の下限 −100.0° を 1.41° 超えるため、
右股関節はそこへ到達できません。**歩かせる前の起立姿勢の時点で 1.30° の左右差**が生じます。

再現スクリプト: `prove_hip_limit_asymmetry.py` / `check_joint_saturation.py`

**(3) 自動生成元の xacro に起因すると推測**

URDF ヘッダに `autogenerated by xacro from khr3_001b.xacro` とあります。
右脚を生成する際に**全関節の可動域を一律に鏡像化**しており、roll 系では正しいものの
pitch 系（hip_pitch）にも適用されてしまった、という形ではないかと推測します。
**根治は xacro 側の修正**になると思われます。

## 実害（四足歩行での例）

当方では KHR-3HV を**胴体を +90° ピッチさせて四足歩行**させる実験をしており、
`hip_pitch` の既定姿勢を −1.77 rad（−101.4°）に置いています。

- **既定姿勢が `r_hip_pitch` の下限 −1.745 rad（−100.0°）を 1.41° 超過**しており、
  起動時点でクランプされます（全 24 関節中、既定値が可動域外なのはこの関節だけです）。
- 学習結果の実測:

| バージョン | 左 `hip_pitch` | 下限への張り付き | 右 `hip_pitch` | 下限への張り付き |
|---|---|---|---|---|
| 初期版 (v7) | −95.1 〜 −71.8° | 0 % | **−100.3 〜 −100.0°** | **100 %** |
| 初期版 (v8) | **−110.7 〜 −109.3°** | **100 %** | **−100.4 〜 −99.8°** | **100 %** |
| 現行版 (v28) | −110.4 〜 −90.3° | 11.7 % | −99.1 〜 −82.8° | 0 % |

初期版では**両股関節が可動域に張り付いて事実上ロック**されており
（可動範囲 左 1.4° / 右 0.6°）、歩容が膝と足首だけで作られていました。
現行版でも**左右が約 10° ずれた別々の角度窓**で動いており、歩容の左右非対称（8〜11°）の原因です。

**二足歩行では影響しません。** 既定姿勢が −0.5 rad（−28.6°）で、
非対称の境界（±100°）から 60〜73° 離れているためです（実測で確認済み。左右差 1.91°）。
**四足化で股関節を −101.4° に置いたことで初めて表面化しました。**

## 当方での暫定対処

- `r_hip_pitch` の可動域を `l_hip_pitch` と同一（−1.919862177, +1.745329252）にした
  **別名ファイル** `khr3hv_symhip.urdf` を追加して使用（**元ファイルは一切変更していません**）。
- 併せて、Genesis の `rigid_solver.set_dofs_limit()` で**実行時に上書き**する方法も用意しました
  （アセットを変更せずに済む方法）。

## ご確認いただきたい点

1. `khr3_001b.xacro` 側で `hip_pitch` の可動域が鏡像化されていないか
2. **実機 KHR-3HV の hip_pitch 可動域が実際に左右対称か**
   （もし実機が本当に非対称なら、当方の「修正」の方が実機から乖離することになります）
