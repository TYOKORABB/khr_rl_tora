# v31 の実機歩行と学習環境のずれの原因探し（2026-10-14、実機なし）

10/13 の v31-s2 の実機歩行（`real/data/raw/walk_20261013_201837.npz`、歩行 5 回・108 秒）を使い、
学習環境（Genesis、CPU）で条件を変えて、実機とのずれがどの違いで再現できるかを調べた。**同定ではなく感度の確認**。
コードは `sysid/`（`closed_loop.py`・`walk_sweep.py`・`sim_replay.py`）。

## 何がずれていたか（歩行 3〜5 の平均。学習環境は物理・観測とも既定）

| 量 | 実機 | 学習環境 | 実機 3 回のばらつき（標準偏差） |
|---|---|---|---|
| 横の傾き（区間の平均） | +0.6〜+3.4°（左が下） | −2.9〜+1.0° | 0.18° |
| 前後の傾き | −4.5〜−12.2°（頭が上） | −2.6〜−9.7° | 0.27° |
| 旋回の速さ / 指令 | 0.88 | 1.03 | 0.01 |
| 関節の指令と実測の差（平均） | 1.2〜2.2° | 1.0〜1.9° | — |
| 可動域の端にいた割合（後退 / 右旋回） | 61 % / 39 % | 55 % / 17 % | — |

**止まって立っているとき（各歩行の直前、初期姿勢で保持）にも同じ向きのずれがある**: 実機 − 学習環境 = 横 +1.5°・前後 −3.0°。
動きの違いではなく、一定のずれ（IMU の取り付け回転の誤差、または形・関節の 0 点の違い）が主。

## 1. 条件を 1 つずつ変える（閉ループ、`walk_sweep run --set percond` ほか、`walk_sweep/summary.md`・`sweep_effects.png`）

方策を walk_session と同じ観測の作り方で動かし（`closed_loop.py`。既存の 1 体版と 3 秒までビット単位で一致を確認）、
条件を 1 つ変えたときの変化（区間の平均）:

| 条件 | 横の傾き | 前後の傾き | 旋回の比 | 関節の差 |
|---|---|---|---|---|
| 摩擦 0.2〜1.0（既定 0.5） | −0.1〜+0.1° | −0.0〜+0.2° | −0.03〜+0.03 | 0 |
| 胴体の質量 +0.1〜+0.5 kg | −0.05〜−0.5° | +0.2〜+1.0° | ±0.03 | 0 |
| 重心 前後・左右・上下 ±2 cm | −0.4〜+0.2° | −0.2〜+0.3° | ±0.01 | 0 |
| kp ×0.6〜×1.25 / kd ×0.5〜×2 / トルク上限 ×0.7 | −0.3〜0° | −0.1〜+0.3° | **kd ×2: −0.085**、kp ×0.6: −0.066 | −0.2〜+0.2° |
| 行動の遅れ +20 / +40 ms | −0.1° | −0.1° | **−0.031 / −0.075** | **+0.33 / +0.60°** |
| 関節の 0 点のずれ ±2°（一様乱数 8 通り、方策からは見えない） | −1.3〜+1.1° | 0〜+1.0° | −0.05〜0 | 0 |
| **IMU の取り付け誤差 横 ±2・±4°** | **+2.7 / +5.4°（ほぼ 1:1）** | ±0.3° | ±0.04 | 0 |
| **IMU の取り付け誤差 前後 ±2・±4°** | ±0.2° | **∓2.1 / ∓4.2°（ほぼ 1:1）** | ±0.02 | 0 |

- **方策は胴体の傾きを決まった値に戻そうとしない**。質量・重心・摩擦・PD ゲインでは、方策が見る傾きは 1° 未満しか変わらない。
  IMU の誤差は、そのまま見える傾きに足される。
- 旋回が指令より遅い（0.88）のは、遅れか減衰（kd）を増やす方向で再現する。関節の差も遅れ +20 ms でほぼ実機の値になる。

## 2. 組み合わせ（`--set combo`、kp・kd を変えて 3 プロセス）

IMU（横 +2/+3°、前後 −2/−3°）× 遅れ（+0/+20/+40 ms）× 摩擦（0.5/1.0）× PD（既定・kd ×2・kp ×0.8）。
実機 − 学習環境の残差がいちばん小さかったのは **IMU 横 +2°・前後 −2°、遅れ +20 ms、kd ×2**（摩擦 0.5 と 1.0 はほぼ同じ）:

| 残差（実機 − 学習環境） | 既定の学習環境 | 最良の組み合わせ |
|---|---|---|
| 横の傾き 平均 / RMS | +2.60 / 2.88° | −0.01 / 1.13° |
| 前後の傾き 平均 / RMS | −2.51 / 2.59° | −0.10 / 0.47° |
| 旋回の比 | −0.152 | −0.051 |
| 関節の差（平均） | +0.28° | −0.23° |
| 可動域の端（後退 / 右旋回） | +6 / +22 % | −1 / −2 % |

横の傾きは区間ごとの違い（RMS 1.1°）が残る。粗い格子で、同じずれを別の条件の組でも作れる（傾き: IMU の誤差 ⇔ 形・0 点の違い、
旋回: 遅れ ⇔ 減衰）ので、**これは一つの説明であって同定値ではない**。

## 3. 区間再生 E4a（開ループ、`sim_replay.py`、`sim_replay/*.json`）

記録を 1 秒ずつ 103 区間に切り、各区間を実機の関節角・重力・ジャイロから始め、実際に送った目標角で学習環境を動かした（方策は使わない）。
胴体の向きは重力に合うよう公称姿勢から最小の回転で傾け（区間の最初の傾きの誤差は 0）、高さはいちばん低い衝突形状が床に触れる位置。

| 物理 | 脚の関節 | 腕の関節 | 胴体の傾き | 傾きのずれの向き（実機 − 学習環境） |
|---|---|---|---|---|
| 既定（遅れ 20 ms、M0） | 0.83° | 0.58° | 2.89° | 横 +1.97 ± 0.89°、前後 −2.13 ± 0.69° |
| 遅れ 20 ms・kd ×2 | 0.60° | 0.45° | 2.97° | — |
| 遅れ 40 ms・kd ×1 | 0.67° | 0.48° | 2.91° | — |
| 遅れ 60 ms | 1.20° | 0.70° | 2.95° | — |
| **IMU 横 +2°・前後 −2° を補正 ＋ kd ×2** | **0.59°** | **0.44°** | **1.51°** | 横 +0.05 ± 0.89°、前後 −0.10 ± 0.70° |

（区間ごとの RMS の中央値。遅れと kp・kd の 18 通りは `sim_replay/grid_*.json`）

- 胴体の傾きは区間の最初の 0.2 秒で約 3° ずれ、そのまま一定。向きは指令によらずほぼ同じ（横 +1.0〜+3.3°、前後 −1.6〜−3.2°）。
- 最後の行の改善は歩行 1〜5 のどれでも同じ程度（脚 −25〜−33 %、傾き −30〜−60 %）。歩行 1・2 は閉ループの組み合わせ選びに使っていない。
  ただし kd と遅れはこの記録の全区間で選んだので、計画書の E4a の合格条件（保留したデータで M1 が中央値 30 % 以上改善）にはまだ当たらない。

## 結論と次にやること

1. **傾きのずれ（横 +2°・前後 −2〜−3°）は止まっていても出る一定のずれ**。いちばん単純な説明は IMU の取り付け回転の推定誤差
   （6 姿勢の校正の残差は最大 2.94°、`real/calib/imu_mount.json`）。左右対称な衝突形状では横のずれは作れないので、横は IMU か関節の 0 点のずれ。
   → 実機で切り分ける: 四脚姿勢で静止させ、胴体に当てた水準器の値と IMU の値を比べる（水準器と IMU が合えば形の違い、合わなければ IMU）。
2. **旋回 88 % と関節の追従は、遅れ（実機の実効の遅れが学習環境より約 20 ms 長い）か減衰で説明できる**。
   → E1-lite（ステップ応答）で遅れと減衰を分ける。指令から実測までの遅れは `fw_check latency` の往復 15〜20 ms に、サーボ自身の応答が加わる。
3. 学習への反映（起き上がり・歩行の次の版）: IMU の重力バイアス ±3°、行動の遅れ 20〜40 ms の乱数化（計画書 §4.6 の案と一致）。
4. 観測の古さの影響は `experiments/real/p03_obs_check.json`（P0-3）: 0〜10 ms なら学習時のノイズ内、0〜20 ms で角速度が超える。
