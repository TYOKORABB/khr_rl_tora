## 測り方

| 測定 | 条件 | ファイル |
|---|---|---|
| 指令の達成率 | 1 つのチェックポイントにつき 5 つの指令（前進 0.3・後退 0.3・左へ 0.15 m/s・左旋回 0.5 rad/s・停止）を 6 体ずつ、2 秒の助走のあと 8 秒。達成率 = 速度の平均 ÷ 指令 | `v31_progress_s<seed>.json` |
| 押しへの強さ | 上と同じで、学習の最後と同じ全強度の押し（3 秒ごと、向きはランダム、大きさは最大 1.0 m/s の速度のけり）を入れる。30 体 × 8 秒の転倒を、押しの乱数の種を変えて 3 回測った合計 | `v31_progress_push_s<seed>.json`（種 0）・`v31_progress_push_r1_s<seed>.json`・`_r2_` |
| 歩き方 | 41 個すべてで、`khr_quad_eval_metrics.measure` で前進 0.3 m/s を 8 体 × 10 秒（膝の振れ幅・足上げ・トルクなど） | `v31_gait_s<seed>.json` |

共通: 行動の乱数なし（平均の行動）・観測ノイズなし・摩擦などの乱数化なし・個体差（関節の 0 点のずれ）なし。
測定ごとに乱数の種を 0 にしてから reset する。環境は seed ごとに 1 回だけ作り、チェックポイントを読み替えて使う。
新しく作った環境で測り直すと、違いは達成率で 1 点以内だった（400・2000 回目で確認）。
完成した方策の値は是正後の 3 seed の測定（`docs/DevelopmentDiary_v2.md` §6.3、GPU・個体差あり・128 体）とほぼ同じになった（前進 78 %、後退 88 %、横 70 %、旋回 101 %）。

## 分かったこと（3 seed で同じ流れ）

1. **0 回目**: 平均の行動では、最初の姿勢のまま立っているだけ（膝の振れ幅 0.1〜0.2°）。
   学習の始めに転び続けるのは、行動に足している乱数（標準偏差 0.5、`Policy/mean_std`）のせい。
2. **100〜300 回目: 最初にできるのはその場旋回**。旋回の達成率が 100 % に近づく時期は seed 2 が 100 回目、seed 1 が 200 回目、seed 3 が 300 回目。
   この時期は、前後・横にはまだ進めない。
3. **300〜400 回目: 前後に歩き出す（動作が出来始める）**。前進は 300 回目で 8〜43 %、400 回目で 54〜71 %。
   足を上げ始め（後脚 3〜9 mm）、トルクも上がる。横歩きはまだ 8〜16 %。
4. **〜1000 回目: 前後の速さはほぼ完成**。前進 74〜83 %は最後（74〜78 %）と同じ水準。横歩きは 50〜55 %。
5. **〜2000 回目: 押されても転ばなくなる**。押されて転ぶ回数（3 回の合計）は、歩き出した 300〜1000 回目に多く（seed 1 で 26〜38 回、seed 2・3 は 7〜18 回）、
   1500 回目で 4〜12 回、2000 回目で 0〜3 回、2300 回目で 3 seed とも 0。学習の押しの強さが最大になる 2080 回目（`push_curriculum_steps` 50000 ÷ 24）とほぼ同じ時期。
6. **2000〜4000 回目: 横歩きが伸び、脚を大きく振る**。横は 58〜72 % → 67〜73 %、膝の振れ幅 18〜19° → 25〜34°、後脚の足上げ 11〜14 → 16〜19 mm。
   前進の達成率とトルクの 99%点はほぼ変わらない。
7. 前進の達成率（3 seed の平均）は 600〜1200 回目が 78〜80 %でいちばん高い。1600〜2900 回目は 71〜76 %に少し下がり、3000 回目より後に 74〜78 %へ戻る。
   学習中の報酬が 1000〜2500 回目にへこむのと同じ時期で、押しが強くなっていく時期と重なる（因果は確かめていない）。

## 動画の作り方

8 つの時点（0・100・300・400・1000・2000・3000・3999 回目）を、同じ指令の列で 1 体ずつ動かした（seed 1・2・3 で同じ）。
指令の列は、前進 3 秒 → 横から押す → 前進 2 秒 → 左旋回 2.5 秒 → 左へ 2.5 秒 → 後退 2.5 秒。
横からの押しは、ロボットの右から胴体の水平の速度に 1.0 m/s を加える（学習の押しの最大と同じ強さで、向きを固定）。
各時点の前に区切りの画面を入れ、3 seed の数字の表を出す（その動画の seed の行を明るく）。説明の数字は `--stats_prefix` で測定のファイルから入れる。
動画の中の押しは 1 回だけの例なので、押しへの強さは上の表の転倒の回数で判断する。
押されて転んだのは、seed 1 が 100・300・400 回目、seed 2 が 400 回目、seed 3 が 100・400・1000 回目。どの seed も 2000 回目からは歩き続けた。

```bash
python quad/khr_quad_progress.py measure -e khr-quadruped31-s1 -o experiments/quad_progress/v31_progress_s1.json
python quad/khr_quad_progress.py measure -e khr-quadruped31-s1 --push -o experiments/quad_progress/v31_progress_push_s1.json
python quad/khr_quad_progress.py measure -e khr-quadruped31-s1 --push --rng_seed 1 -o experiments/quad_progress/v31_progress_push_r1_s1.json  # r2 も同じ
python quad/khr_quad_progress.py gait -e khr-quadruped31-s1 -o experiments/quad_progress/v31_gait_s1.json   # 既定は保存したすべて
python quad/khr_quad_progress.py plot --data experiments/quad_progress/v31_progress_s{1,2,3}.json \
  --push_data experiments/quad_progress/v31_progress_push*_s{1,2,3}.json --mark 0 100 300 400 1000 2000 3000 3999 \
  -o experiments/quad_progress/v31_progress.png
DISPLAY=:1 python quad/khr_quad_progress.py record -e khr-quadruped31-s2 --stats_prefix experiments/quad_progress/v31 \
  --schedule "0.3,0,0:3;push:0,-1.0;0.3,0,0:2;0,0,0.5:2.5;0,0.15,0:2.5;-0.3,0,0:2.5" --card_s 5 \
  --intro_image experiments/quad_progress/v31_progress.png --intro <見出し> <副題> <本文…> \
  --stage 0 "学習の前" "<説明（/ で改行。{fwd#2} などは測定の数字に置き換わる）>" --stage 100 ... --outro <見出し> <本文…> \
  -o media/videos/quad_progress/v31-s2_progress.mp4
```

1 つのチェックポイントの測定は CPU で約 10 秒。seed ごとに別のプロセスにすると、3 seed × 41 個が約 6 分で終わる。動画の書き出しは約 2 分。
