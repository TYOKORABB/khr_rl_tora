# khr-quadruped26 (v26) 事前調査記録 — 足裏水平の罰が「蹴り出し」に浪費されていた

- 記録日: 2026-08-21
- 位置づけ: v25 で横ずれ・旋回対称性・速度は大きく改善したが、**足裏傾きが悪化**した
  （v23 7.29° → v25 11.40°）。ユーザ要求「足の裏全体を使い、踵だけ／つま先だけで歩かない」に
  反する方向であり、本版はこの 1 点に絞る。
- 環境: `khr_quad_env20.py`（env19 からの派生）／学習: `khr_train_quad26.py`

## 1. 診断 — 位相分解して初めて分かったこと

### (a) 傾きは「着地時」ではなく「蹴り出し時」に出ている

接地期を位相で分割して傾きを測った（8体・10秒・個体差あり）。

| 版 | 接地平均 | **着地の瞬間** | 立脚前期 | 立脚中期 | **蹴り出し** |
|---|---|---|---|---|---|
| v22 | 6.59° | 2.83° | 1.65° | 4.46° | 12.80° |
| v23 | 7.29° | 3.22° | 1.65° | 5.13° | 13.53° |
| v24 | 10.59° | 6.23° | 5.26° | 9.41° | 15.10° |
| **v25** | 11.40° | **5.80°** | 3.50° | 8.38° | **18.82°** |

- **着地は比較的平ら**（v25 で 5.80°）で、そこから接地中に徐々に傾き、蹴り出しで最大になる。
- 蹴り出しの符号は **+3.31°（つま先下がり）** ＝ **踵から着いてつま先で抜ける正常なロールオーバー**。
- つまり v25 の「悪化」の大半は**蹴り出しの深さが増したこと**であり、
  「つま先だけで歩く」という異常ではない。

### (b) しかし罰は、その正常な蹴り出しに 7 割が費やされていた

実際に罰される量 `tilt²` の配分を実測した。

| 版 | 着地直前 | 立脚前期 | 立脚中期 | **蹴り出し** |
|---|---|---|---|---|
| v23 | 9.1 % | 0.8 % | 16.7 % | **73.3 %** |
| v25 | 9.8 % | 1.9 % | 18.2 % | **70.1 %** |

**本当に平らにしたい着地には約 10% しか圧力が掛かっておらず、
7 割は「罰する理由のない正常な蹴り出し」に浪費されていた。**

`tilt²` は二乗なので、傾きの大きい蹴り出し（18.8°）が
着地（5.8°）の約 10 倍の重みを持ってしまうことが原因である。

### (c) これは本研究で 5 例目の同型の誤り

| 版 | 誤り | 修正 |
|---|---|---|
| v13 | クリアランスを**絶対高さ**で測っていた | 接地基準からの**相対量**へ |
| v16 | 膝の**絶対角度**を報酬化（報酬ハック） | **swing−stance の差分**へ（v17） |
| v21 | 対称性を**トルク差**で測っていた | **接地 duty 差**へ（v22） |
| v24 | 直進性を **yaw 角速度（率）** で測っていた | **累積量**へ、かつ**観測にも入れる**（v25） |
| **v25** | 足裏水平を**接地期全体**で測っていた（罰の7割が蹴り出しへ） | **着地〜立脚中期に限定**（本版） |

**設計則の一般形**: 「望む結果そのもの」を、**望む局面で**測る。
量の取り方だけでなく、**どの局面を対象にするか**も「測る対象」の一部である。

## 2. v26 の変更（1点）

| 変更 | 内容 |
|---|---|
| **蹴り出し期を罰の対象から外す** | `feet_orientation_pushoff_phase = 0.35` を新設。接地中でも `leg_phase >= 0.35` は足裏水平を要求しない。着地直前（`>= 0.85`）の要求は維持 |

- **スケール `feet_orientation` は −4.5 のまま変えない。**
  対象を絞るだけで、着地に掛かる圧力は実効的に約 10 倍になる。
- 罰を強めるのではなく**配分を正す**変更なので、速度やトルクへの悪影響は小さいと見込む。
  むしろ蹴り出しが自由になることで**推進が改善する可能性**がある。

### 事前スモークテスト（学習前・num_envs=4）
- v25 との設定差が **`feet_orientation_pushoff_phase` の 1 件のみ**であることを機械的に確認。
- AST 比較で中身が異なるメソッドは `__init__`（設定読み出し）と `_reward_feet_orientation` のみ。
- **マスクの挙動を直接検証**:

| 局面 | 接地中の罰 | 遊脚中の罰 |
|---|---|---|
| 立脚前期 (phase 0.05) | 0.000267 | 0 |
| 立脚中期 (phase 0.30) | 0.000267 | 0 |
| **蹴り出し (phase 0.45)** | **0（罰されない）** | 0 |
| 着地直前 (phase 0.90) | 0.000267 | 0.000267（維持） |

- 報酬 finite。

## 3. 合否指標（v23 baseline のノイズ床に対する 2σ 検定 / v25 との比較）

| 指標 | 目標 |
|---|---|
| **足裏傾き（着地の瞬間）** | v25 の 5.80° → **3.5° 以下**（v23 の 3.22° 水準まで戻す。本版の主目的） |
| 足裏傾き（立脚前期） | 3.50° → **2.0° 以下** |
| 足裏傾き（蹴り出し） | 悪化は許容（推進に必要な正常動作。ただし 30° 未満に留めたい） |
| **横ずれ率（個体差あり）** | v25 の 2.88% を維持（悪化させない） |
| **90%超の時間** | **0.00% 維持（必須）** |
| 前進速度 | v25 の 0.239 を維持（低下させない） |
| 膝 ROM | 33° 前後を維持 |

> **反証可能性**: 着地時の傾きが下がらなければ、「罰の配分が原因」という診断は棄却される。
> その場合は `feet_orientation` の強化か、着地の傾きを直接罰する専用報酬を次に試す。
