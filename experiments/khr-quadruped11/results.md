# khr-quadruped11 (v11) 検証結果 — ❌ 失敗（並進が崩壊）

- 記録日: 2026-07-29（学習: 4096env × 4000iter, seed=1, 所要1h30m, 最終 model_3999。学習は完走）
- 対策の意図は同ディレクトリ `investigation.md` を参照。**結論: yaw罰が強すぎて並進歩行が崩壊。不採用。**

## 1. 症状: 並進（前後左右）が消えた

6方向実測（ノイズ/DR無効、前進は在範囲0.3）:

| 方向 | 指令 | 実測 | 追従率 |
|---|---|---|---|
| 前進 | (+0.30,0,0) | (+0.083,+0.069,+0.014) | **28%**（横0.069＝斜行） |
| 後退 | (−0.20,0,0) | (−0.000,+0.000,+0.001) | **0%** |
| 左横 | (0,+0.15,0) | (−0.000,+0.000,+0.006) | **0%** |
| 右横 | (0,−0.15,0) | (−0.000,−0.000,+0.004) | **0%** |
| 左旋回 | (0,0,+0.50) | (+0.036,+0.041,+0.426) | 85% |
| 右旋回 | (0,0,−0.50) | (−0.016,+0.054,−0.460) | 92% |

- 学習末尾の `rew_tracking_lin_vel` = **0.318**（v10 は 3.56 の約1/10）。
- 前進の軌跡は正味変位ほぼ0（＝前進成功ではなく"ほぼ静止"）。**旋回だけ生き残った**。

## 2. 原因: yaw罰(weight=5.0)が並進を潰した

- v11 は `_reward_drift` の yaw 成分を横成分の **5倍** に重み付け（`yaw_drift_weight=5.0`）。
- トロット歩容は前進時に自然と小さな yaw 揺れを生む。これを5倍で罰したため、
  **「並進すると大きな yaw 罰を食らう」→「並進しない方が得」** という degenerate 解に収束。
- `tracking_lin_vel` は exp 罰なので低速でも報酬が残り（0.083m/sでも約73%の報酬）、
  並進を捨てても損が小さかったことも後押しした。
- 旋回指令時は `wz_err = wz − cmd_wz ≈ 0` で罰がかからないため、旋回だけ生き残った。

## 3. 学び（卒論の失敗記録として価値あり）

- **瞬時の yaw 誤差を強く罰すると、歩容が本来もつ周期的な yaw 揺れまで罰してしまい、
  並進そのものを抑制してしまう。** 直進性を上げたいなら「瞬時値」ではなく
  **「持続的なヘディング偏り（時間平均）」を罰す**べき。
- → v12 で対策: 瞬時 yaw 罰は v10 相当(重み1.0)に戻し、`wz_err` の EMA（持続的な首振り偏り）
  を別途罰す。これなら周期的な揺れは平均で消え、並進を潰さずに真っ直ぐ化できる見込み。

## 4. 扱い

- **v11 は不採用**。実機に載せない。次版 v12（khr-quadruped12）で修正する。
- v11 の成果物(logs/khr-quadruped11, 本ディレクトリ)は失敗記録として保持。
