## 1. 実機フィードバック（教授）

v8 (khr-quadruped8) を実機 KHR-3HV で動作させ、教授に確認いただいた際の指摘:

1. **動きがぎこちない**
2. **モーターのトルクが最大になっている可能性**
3. **後退ができない**

（研究の方向性は正しく進捗も良好、との評価。以後はシミュ上での四足歩行精度向上を進める方針。）

## 2. 定量診断（v8 model_3999, ノイズ/DR無効の実測）

### 決定的発見: 後脚 hip_pitch が常時トルク100%飽和

前進(0.4)・横(0.15)・旋回(0.5) の全モードで、左右 `hip_pitch` が定格トルク(1.373Nm)に
**100%張り付き**、かつ **PD目標角から50〜66度ズレ続けていた**（＝指令位置に到達できていない）。

| 動作 | 飽和関節 | トルク duty | 平均負荷 | 追従誤差 |
|---|---|---|---|---|
| 前進 | l/r_hip_pitch | 100% | 100% | 59.8° / 47.2° |
| 横 | l/r_hip_pitch | 100% | 100% | 51.5° / 52.6° |
| 旋回 | l/r_hip_pitch | 100% | 100% | 66.1° / 55.9° |
| 他20関節 | — | 数%〜27% | 〜58% | 1〜4°（正常追従） |

### 静的 vs 動的の切り分け（ハード弱ではなく方策の問題）

| 条件 | hip_pitch トルク | 定格95%超の関節 |
|---|---|---|
| 初期姿勢で静止保持（4脚接地） | **43%**（0.587Nm） | **0/22** |
| 歩行中 | **100%（張り付き）** | 2/22（＝l/r_hip_pitch） |

→ 同じ姿勢を静的には43%で楽に支えられるのに、歩行時だけ100%飽和。遊脚中も含め duty=100%。
**方策が hip_pitch を飽和させる bang-bang 制御として使う歩容を学習した**（到達不能な角度を指令し続け、
サーボが限界で引きずられている）。シミュは飽和で受け止め前進するが、実機では
**「モーター全開＋カクつき」**として現れる ＝ 教授指摘①②の正体。

### 原因

現行報酬で飽和がほぼ罰せられていない。`joint_torques` は `−0.0005×τ²`＝飽和時でも
1関節あたり約−0.0009で、追従報酬4.0に対し無視できる。よってPPOは hip_pitch を
振り切る歩容を平然と選ぶ。

### ③ 後退

`command_cfg.lin_vel_x_range = [0.0, 0.4]`。負の vx を一度も学習しておらず、後退指令時の
実測追従は7%（ほぼ静止・転倒せず）。純粋に学習範囲外＝バグではない。

## 3. v9 の対策（環境 khr_quad_env6 / 学習 khr_train_quad9）

根本原因（hip_pitch のトルク飽和・到達不能指令）を報酬で直接叩き、あわせて後退を開放する。
初期姿勢・kp/kd・action_scale・ネットワークは v8 のまま（変更を報酬とコマンド範囲に限定）。

| ラベル | 対応指摘 | 変更 |
|---|---|---|
| **A** | ② | `_reward_torque_limits` 新設・scale **-2.0**。定格の85%(`torque_soft_ratio`)超のトルクを罰し飽和を抑制（補助） |
| **B** | ①② | `_reward_dof_pos_error` 新設・scale **-1.0**。PD目標角と実角の誤差を罰し「実現可能な指令」へ誘導（**主対策**） |
| **D** | ① | `acceleration` -0.00002 → **-0.00004**。カクつきの補助的低減 |
| **E** | ③ | `lin_vel_x_range` [0,0.4] → **[-0.2, 0.4]**（後退開放。前進0.4/後退0.2） |

実装の要点:
- effort limit は URDF から `get_dofs_force_range` で取得（1.373Nm を確認）。
- PD目標角は env の `step` で `target_dof_pos = exec_actions*action_scale + default_dof_pos`
  （1step遅延あり）を `self.target_dof_pos` に保持し、B で参照。

### 事前スモークテスト（学習前・num_envs=4）

- 後退範囲 [-0.2, 0.4] を確認、報酬メソッド対応 全20項 OK、torque_limit=1.373 取得。
- 大振幅アクションで `_reward_torque_limits`=0.742 / `_reward_dof_pos_error`=0.913（飽和・到達不能を検知）、
  step報酬は finite。→ 環境・新報酬とも正常動作。

## 4. 学習と検証手順（このあと）

```bash
python khr_train_quad9.py -e khr-quadruped9 -B 4096 -I 4000 --seed 1
python khr_quad_report.py -e khr-quadruped9              # report.md/metrics.csv 生成
# 検証（学習後）: 飽和が解消したかを再診断（hip_pitch duty・追従誤差・滑らかさ）
#                前後左右・旋回の追従率と動画(khr_quad_record6.py)
```

### v9 の合否を見る指標（v8比）
- **hip_pitch のトルク duty>90% が 100% → 大幅低下**（狙い: ②解消）
- **hip_pitch の追従誤差 50〜66° → 数度**（狙い: ①②解消）
- **|Δaction|RMS / dof_vel RMS の低下**（狙い: ①滑らかさ）
- **後退 vx=-0.2 の追従が改善**（狙い: ③）
- 前進/横/旋回の追従率が大きく落ちていないこと（トレードオフ確認）

> 注意: B/A の scale は初期値。学習後に hip_pitch 飽和が残る場合は B を強め、
> 逆に歩容が消える(立ち止まる)場合は B を弱める。必要なら候補C（hip系の action_scale/kp 低減）を次版で。
