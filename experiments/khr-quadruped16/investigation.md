# khr-quadruped16 (v16) 事前調査記録 — 遊脚期の膝屈曲を直接報酬にする

- 記録日: 2026-07-31
- 位置づけ: v15 で特定した真因（膝を動かす**指令自体が出ていない**）への直接対策。
  目標は「犬のようにスムーズに関節を動かす歩行」（ユーザ）。方針は [[project_roadmap]]。

## 1. 前提: v15 で真因が確定している

PD の**指令角**と**実測角**の可動域を比較した結果（v15, 前進0.3）:

| 関節 | 指令ROM | 実測ROM | 追従率 |
|---|---|---|---|
| l_hip_pitch | 14.2° | 15.6° | 110% |
| **l_knee_pitch** | **6.8°** | 7.8° | 114% |
| l_ankle_pitch | 13.0° | 12.6° | 97% |
| r_hip_pitch | 14.6° | 15.0° | 102% |
| **r_knee_pitch** | **7.4°** | 8.4° | 115% |
| r_ankle_pitch | 12.2° | 11.8° | 96% |

**膝の指令 ROM 自体が 6.8〜7.4° しかなく、実測はむしろそれを上回っている。**
⇒ トルク不足でも PD の追従限界でもなく、**方策が膝を動かす指令を出していない**。
原因は完全に**報酬設計**（`torque_limits` は容疑から外れた）。

### なぜ膝を使わないのか
- 遊脚は**股関節の回転だけ**（hip ROM 15°）で振られている。
- **膝の屈曲を直接求める報酬が存在しない**。`feet_clearance` は足の高さしか見ないため、
  股関節主体でも部分的に満たせてしまう（ただし剛体脚の円弧運動では高さを稼げず、
  後脚クリアランスは 0.007〜0.010m で頭打ち）。
- 一方で関節運動には広くコストがかかる（`dof_vel` −0.001, `action_rate` −0.02,
  `action_smoothness2` −0.01, `acceleration` −0.00004, `dof_pos_error` −1.0）。

⇒ **「膝を曲げる利益が無く、動かすコストだけある」**ため、膝を固めて股関節だけで振るのが最適解。
これは犬・馬が**遊脚期に膝を畳んで脚を短縮し地面を避ける**のと正反対の戦略である。

## 2. v16 の対策（環境 khr_quad_env13 / 学習 khr_train_quad16）

**変更は1点のみ**（ablation を明確化するため）。

| 変更 | 内容 |
|---|---|
| `_reward_knee_flexion` 新設・`"knee_flexion": 2.0` | **後脚の膝が遊脚期に default(0.40rad) より曲がっているほど加点**。目標 +0.30rad、sharpness 10 の指数報酬。**接地期は対象外**にして支持脚の剛性は保つ |

- 膝は片方向可動（`[0.0, 2.793]` rad, default 0.40）なので、**default より大きい側が屈曲**。
  目標 0.40+0.30 = 0.70 rad は可動域内に十分収まる。
- 対象は後脚のみ（`l_knee_pitch`, `r_knee_pitch`）。前脚はユーザ指示により v12 水準を維持。
- 据え置き: 足裏水平の接地限定(v15)、脚別クリアランス目標（前0.012/後0.02）、`base_height` −3.0、
  `torque_limits` −5.0、`dof_pos_error` −1.0、`leg_load_balance`、`heading_drift`、`feet_air_time`。

### 事前スモークテスト（学習前・num_envs=4）
- scale 2.0 / target 0.30 / sharpness 10 反映、全26報酬のメソッド対応 OK、報酬 finite。
- 膝 index = [11, 17]（`l_knee_pitch`, `r_knee_pitch`）、後脚 phase index = [2, 3] を確認。
- **報酬が屈曲に反応することを検証**: 全脚を swing 扱いにして
  屈曲なし = 0.0996 / 目標屈曲(+0.30rad) = 2.0000。

## 3. 学習と検証（このあと）
```bash
python khr_train_quad16.py -e khr-quadruped16 -B 4096 -I 4000 --seed 1
python khr_quad_report.py -e khr-quadruped16
```
### v16 の合否指標（v15比）
- **膝 ROM の回復（主目的）**: 7.2/7.8° → 増加（v8 の 22.3° が一つの目安）。
  併せて**指令 ROM** も増えていることを確認する（報酬が指令を変えたかの直接確認）。
- **後脚クリアランスの増加**: 0.010/0.007m → 目標 0.02m へ。
- **足首と膝の役割の是正**: ankle(24/22%) が knee(17/15%) を上回る状態の解消。
- **トルク安全性の維持（必須）**: 飽和 0/22、ピークが定格80%を超えないこと。
- **接地の質**: 足裏傾き（接地時平均 13.5°）が更に悪化しないこと。
- 追従（前進75/後退61/左横90/右横69%）・エピソード長が大きく崩れないこと。

> scale 2.0 は初期値。膝が暴れて着地の質やトルクが悪化するなら弱め、効果が出なければ強める。
