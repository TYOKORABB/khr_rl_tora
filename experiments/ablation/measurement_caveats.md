# 測定手法の重大な訂正（2026-10-04）— ピーク判定の無効化と、横ずれの不安定性

転倒率・歩容一致率を評価ツールに追加する過程で、**これまでの判定基準に2つの誤り**を見つけた。

## 1. ❌ 「トルクピーク < 90%」という安全判定は無効だった

同一ポリシー（v27 seed1）を体数だけ変えて測ると:

| 体数 | ピーク | 99%点 | 90%超の延べ時間 |
|---|---|---|---|
| 8 | 85.4 % | 59.3 % | 0.0000 % |
| 32 | 91.5 % | 59.2 % | 0.0007 % |
| 128 | **94.7 %** | 59.4 % | 0.0004 % |

**ピークは体数とともに単調に上がる。** 最大値は**極値統計**なので、母数を増やせば必ず大きくなる。
一方 **99%点と「90%超の延べ時間」は体数にほとんど依存しない。**

→ **「ピーク 90% 未満」を合否の閾値に使っていたのは誤り。**
8 体で測った 86.4%（v27）も、128 体で測れば 93.7% になる。
この基準で `g1smooth`（93.1%）と `g2posture`（91.8%）を「安全要件違反」と判定したが、
**同じ体数で測った v27 自身が 128 体では 93.7%** であり、判定は成立しない。

> 皮肉なことに、開発日誌 §4.x で「ピークは稀事象の統計なので平均・パーセンタイル・
> 閾値超過時間で見るべき」と自分で書いていながら、安全判定ではピークを使っていた。

### 安定統計での再判定（ノイズ床 2σ）

| 構成 | 99%点 | 判定 | 90%超の延べ時間 | 判定 |
|---|---|---|---|---|
| v27（基準） | 59.4 % | — | 0.0008 % | — |
| g1smooth | 59.5 % | — | 0.0015 % | — |
| **g2posture** | **63.0 %** | **悪化** | 0.0008 % | — |
| g3jointreg | 59.3 % | — | 0.0000 % | — |
| g4gaittime | 60.9 % | — | 0.0000 % | — |
| g5heading | 58.9 % | — | 0.0000 % | — |
| only-acceleration | 58.7 % | — | 0.0008 % | — |
| only-drift | 60.7 % | — | 0.0004 % | — |
| only-feet_orientation | 53.8 % | 改善 | 0.0000 % | — |
| only-gait_contact | 56.8 % | — | 0.0000 % | — |
| only-alive | 55.8 % | — | 0.0000 % | — |
| only-tracking_lin_vel | 56.8 % | — | 0.0000 % | — |
| **combo9（v28候補）** | **58.8 %** | — | **0.0000 %** | — |

**判定の変更**:
- `g1smooth`: 安全要件違反 → **取り下げ**。ただし**トルク平均 2.2σ 悪化**は残るので削除不可は変わらない（理由が変わった）。
- `g2posture`: 安全要件違反 → **99%点 3.9pt 悪化（2σ=3.76 超）で削除不可**（理由が変わり、結論は同じ）。
- その他は変更なし。**`combo9` は安定統計でも完全にクリーン。**

## 2. ⚠️ 横ずれ率は 8 体では信用できない

評価ツールに**読み取りを 2 行足しただけ**で、既存の測定値が動いた。

| 指標 | 変化 |
|---|---|
| トルク平均 | 17.9274 → 17.9256（0.01 %） |
| トルクピーク | 74.218 → 74.178（0.05 %） |
| 膝 ROM | 35.988 → 35.999（0.03 %） |
| **横ずれ率** | 0.996 → **3.614（263 %）** |

原因は**接触を含む物理のカオス性**で、GPU の float32 の丸め差（カーネル実行順が変われば変わる）が
600 ステップで巨視的な差に増幅される。**ほぼ直進している方策では、最終的な横位置は
決定論的な「方策の性質」ではなく、ほぼカオス的な揺らぎである。**

### 対策: 体数を増やす

| 体数 | 横ずれ率（3回反復） |
|---|---|
| 8 | 2.25 ± 0.63 |
| 32 | 1.87 ± 0.20 |
| **128** | **1.93 ± 0.06** |

σ は体数とともに 1/√n より速く縮む。**横ずれで版間を比べるなら 128 体が必要。**

→ **8 体で測った「横ずれ 2σ 改善」系の判定は、2〜4% の領域では信用できない。**
v24 の 12〜19% のような大きな差は方策の性質だが、v25/v27/combo9 の 2〜4% の違いは
測定のばらつきに埋もれている可能性が高い。

## 3. 追加した指標と、`alive` / `gait_contact` の再測定

評価ツールに **転倒回数** と **歩容一致率**（4脚が位相どおりに接地/離地している時間の割合）を追加した。
これまで**前進指令だけで測り、転倒も歩容も見ていなかった**ため、
`alive`（転倒防止）と `gait_contact`（歩容生成）の効果を検出できる指標が無かった。

**128 体・3 回反復での再測定（個体差あり）**

| 構成 | 転倒 | 歩容一致率 | 横ずれ率 | トルク平均 |
|---|---|---|---|---|
| v27（基準） | **0** | 87.0 % | 3.84 ± 0.08 | 18.12 % |
| `alive` 除去 | **0** | 86.6 % | 2.65 ± 0.06 | 17.13 % |
| `gait_contact` 除去 | **0** | 85.7 % | 2.40 ± 0.11 | 17.45 % |

- **転倒は全構成でゼロ**。10 秒の前進では `alive` を外しても転ばない。
- **歩容一致率は `gait_contact` を外しても 87.0 → 85.7 %（1.3pt）しか落ちない。**
  位相どおりの接地は、`gait_contact` が無くても他の報酬（`feet_clearance` / `knee_swing_flexion` /
  `feet_orientation`）と歩容位相の観測だけでほぼ維持される。

> **限界**: 10 秒・前進指令のみでの結果である。`alive` の価値は
> 「外乱を受けたとき」「長時間」「難しい指令」で現れる可能性が高く、本測定では評価しきれていない。
> 結論を出すなら push 外乱を有効にした測定や、より長いエピソードが必要。

## 4. この件の教訓

1. **閾値で合否を決める指標は、サンプル数に依存しないものを選ぶ。**
   最大値（ピーク）は母数が増えれば必ず上がるので、閾値判定に使ってはならない。
2. **カオス的な系では、指標ごとに「必要なサンプル数」が違う。**
   トルク平均は 8 体で十分だが、横ずれは 128 体必要だった。
3. **測定していない軸では、何も言えない。** 前進指令だけで測って「`alive` は不要」とは言えない。

## 5. 転倒率と歩容一致率の測定結果（2026-10-04）

### 5.1 「転倒ゼロ」は測定条件のせいだった

初回測定で全構成とも転倒 0 だったが、原因は push 外乱が効いていないことだった。

```python
push_scale = min(1.0, self.push_step_counter / self.push_curriculum_steps)   # push_curriculum_steps = 50000
```

`push_step_counter` は env 生成時に 0 から始まるため、評価の 600 ステップでは
**`push_scale = 600/50000 = 0.012`、キックの最大値は 1.0 × 0.012 = 0.012 m/s** しかない。
**実質的に無外乱で測っていた。**

→ 評価ツールに `--push` を追加した（`push_curriculum_steps = 0` にして最初から全強度）。

### 5.2 外乱ありでも、`alive` の効果は検出できなかった

**19 秒・押し 1.0 m/s（3秒ごと）・128 体・3 回反復・個体差あり**

| 構成 | 転倒（3回それぞれ） | 合計 | 延べ体分 | 転倒率 [/体/分] |
|---|---|---|---|---|
| v27 seed1 | [0, 0, 0] | 0 | 109 | 0.000 |
| v27 seed2 | [0, 0, 1] | 1 | 109 | 0.009 |
| **v27 合計** | | **1** | **218** | **0.005** |
| `alive` 除去 seed1 | [1, 0, 1] | 2 | 109 | 0.018 |
| `alive` 除去 seed2 | [0, 0, 0] | 0 | 109 | 0.000 |
| **`alive` 除去 合計** | | **2** | **218** | **0.009** |

**1 件 vs 2 件。統計的には区別できない。**

> **正直な結論**: この条件（19 秒・前進指令・押し 1.0 m/s）では**どちらもほぼ転ばない**ので、
> 指標が床に張り付いており `alive` の価値を測れない。
> 差を解像するには露出を 10〜20 倍（数千体分）にするか、
> もっと厳しい条件（強い押し・地形・長い時間）が必要。
> **現時点で「`alive` は不要」とは言えないし、「必要」とも言えない。**

### 5.3 歩容一致率 — `gait_contact` を外してもほとんど落ちない

歩容一致率 ＝ 4 脚が位相どおり（stance 期に接地 / swing 期に離地）である時間の割合。
`gait_contact` / `gait_swing` が直接狙っている量そのもの。

**外乱なし・128 体**

| 構成 | 全体 |
|---|---|
| v27（基準） | 87.0 % |
| `alive` 除去 | 86.6 % |
| `gait_contact` 除去 | **85.7 %** |

**外乱あり・128 体（前脚／後脚の内訳つき）**

| 構成 | 全体 | **前脚（腕）** | **後脚** |
|---|---|---|---|
| v27（基準） | 85.4 % | 83.2 % | 87.7 % |
| `alive` 除去 | 85.3 % | 83.0 % | 87.6 % |
| `gait_contact` 除去 | 84.8 % | 82.3 % | 87.3 % |
| combo9（v28候補） | 85.4 % | 82.9 % | 87.8 % |

**読み取れること**

1. **`gait_contact` を外しても一致率は 87.0 → 85.7 %（1.3pt）しか落ちない。**
   位相どおりの接地は、この報酬が無くても他の報酬（`feet_clearance` / `knee_swing_flexion` /
   `feet_orientation`）と**観測に入っている歩容位相**（`sin/cos_phase`）だけでほぼ維持される。
   寄与 +0.5676 と 7 番目に大きい報酬だが、**実際の歩容への寄与は小さい。**
2. **前脚（腕）の一致率は後脚より一貫して 4〜5pt 低い**（83% 対 88%）。
   腕を前脚として使う本機の形態上の弱点が、初めて数値で出た。
   腕は脚より軽く可動域も違うため、位相どおりに置くのが難しいと解釈できる。
3. combo9（9 項目除去）は v27 と同じ 85.4 % を維持している。

### 5.4 まとめ

| 問い | 答え |
|---|---|
| `alive` は要るか | **判定不能。** どちらもほぼ転ばず、指標が床に張り付いている |
| `gait_contact` は要るか | **効果は小さい**（一致率 1.3pt）。ただしゼロではない |
| 歩容の弱点はどこか | **前脚（腕）**。後脚より 4〜5pt 位相から外れている |
