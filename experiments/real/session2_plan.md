## 各項目のやり方

### 0. 起動の確認

`python -m real.fw_check listen --seconds 5`。改造版の印（状態語 [11]）が出ていて、通信監視の状態が読め、重力の更新が毎秒約 100 回なら進む。
「改造前のファーム」と出たら（梶田版に戻っていたら）止める。書き直しには BOOT ボタンが要るので、ユーザーに確認してから行う（10/13 に一度起きた）。
ESP32 からデータが届かないときは、PC の IP が変わっていないかを先に見る（ESP32 の送り先は PC の IP に固定）。

### 1. E5-lite（通信）

`python -m real.fw_check latency --seconds 300`（2 通りの送り方 × 5 分）。往復の遅れの分布（中央値・p99・最大）と、
ESP32 → PC で届かなかったフレームの割合（ESP32 が付ける通し番号の飛び）を記録する。10/13 は往復 中央値 15〜20 ms。
歩行・起き上がりの学習の遅れの乱数化の範囲（個体差）を決めるのに使う。

### 2. 符号の確認（3 関節）

`python -m real.servo_jog --line L --idx 3 --amp 10`（左の肘ヨー）、`--line R --idx 3`（右の肘ヨー）、`--line L --idx 0`（頭ヨー）。
そのサーボだけ電源が入り、今の角度から**まず + 方向に 10°**、次に − 方向に 10° 動いて戻る。ロボットは寝かせるか吊るす。
学習環境のモデルでの + の向き（全関節 0 の姿勢で、回転の軸はどれも上向き）:

- 頭ヨー: **上から見て反時計回り**（頭がロボット自身の左を向く）。
- 肘ヨー（左右とも）: 肩の側から手の方を見下ろしたとき**反時計回り**に前腕がひねられる。

最初の動きがこの向きなら符号は +1（今のまま）。逆なら教えてほしい（`khr_common/joint_map.py` を直し、歩行の記録の比べ直しが要る）。

### 3. E1-lite（ステップ応答）

胴体を台に固定し、手足が自由に振れる状態にする（脚と腕が台・床・ケーブルに当たらないこと）。
`python -m real.step_response run`: 全サーボで全関節 0° を保ったまま、左の肩ピッチ・肘ピッチ・股ピッチ・膝ピッチと右の膝ピッチを 1 つずつ、
5° と 15° の段差で動かす（向き 2 つ × 5 回、行きと帰り。約 4 分）。膝は 0° から曲げる側にしか動かせないので、基準を 18° にする。
ぶつかった・押された（動かしていない関節が 5° ずれる）と全サーボ脱力して止まる。

学習環境のモデル（kp 25・kd 0.5・アーマチュア 0.01・1 歩の遅れ）の予測（`python -m sysid.step_sim`、`experiments/sysid/step_sim_train_model.json`）:
段差の 50 % に届くまで、5° で約 48 ms、15° で約 70 ms（大きい段差はトルクの上限で遅くなる）。実機の値がこれとどれだけ違うかで、
「旋回が指令の 88 %・関節の追従が学習環境より大きい」原因（遅れか減衰か、ROBOT_STATUS）を切り分ける。
同定の合格（計画書 §5.3）: 前の 3 回で選んだモデルが、後の 2 回の立ち上がりの時間を ±20 % 以内で当てる。

### 4. 歩行の速さ

床に 2.5 m 以上まっすぐ歩ける場所を取り、スタートの位置（前腕の先と足の先）に養生テープで印をつける。
`python -m real.walk_session serve &` で四脚の初期姿勢にしてから、`python -m real.walk_session go --schedule 0:2,0.3:8,0:2`（前進）を 3 回、
`--schedule 0:2,-0.2:8,0:2`（後退）を 2 回。毎回、止まった位置の前腕の先までの距離と、まっすぐからの横のずれをメジャーで測る。横から固定のカメラで撮る。
学習環境の速さは前進 0.226 m/s・後退 0.192 m/s なので、8 秒でおよそ 1.8 m・1.5 m 進む見込み（足踏みの 4 秒はほぼ動かない）。

### 5. 発熱

4 の前に一度、4 の直後にもう一度、左右の膝・股・肩・肘のピッチのサーボの表面を赤外線の温度計で測る。
足りなければ、40 秒の指令の列（前進・後退・横・旋回）を 3 回続けてから測る。

### 6. 傾きのずれの切り分け

`walk_session serve` で四脚姿勢を保持し、背中の板（胴体）にスマホの傾斜計を当てる。`python -m real.walk_session status` の
`left_down_deg`（左が下）・`head_down_deg`（頭が下）と、傾斜計の値を比べる。10/13 の歩行では、学習環境より横 +2°（左が下）・前後 −2〜−3°（頭が上）ずれていた。
両方が同じだけずれていれば体の形（関節の 0 点）、IMU だけがずれていれば取り付けの校正が原因。

### 7〜10

- 質量: 総質量（g）。四脚姿勢（`walk_session serve`）で前腕 2 本を一方のスケール、足 2 本をもう一方に載せ、前後の荷重を読む。URDF は合計 1.600 kg。
- 電圧: テスターで、サーボ電源の入口の電圧を「脱力」と「四脚姿勢の保持」で。電池か安定化電源かも記録する。
- IMU の残り: `python -m real.imu_tests static --name tilt1`（斜め 4 姿勢）、`rotate --seconds 30`、`drop --seconds 10`。サーボは脱力のまま。
- 床の摩擦: 板にロボット（脱力、うつ伏せ）を載せて傾け、滑り出す角度。足の裏でも同じ。背中のケースは定規を入れて 3 方向から写真。
