# IMU の 6 姿勢試験 1 回目（2026-10-13 19:00 ごろ）— 不合格（置き方の傾き）

計画書 P0-1。BNO055 の取り付け回転 `R_mount`（センサ → base）を、既知の向きに置いたときの重力ベクトルから求める。
合格基準は「全姿勢で誤差 < 3°」。ファームは khr-getup.4（重力の更新 約 100 Hz）。

## やり方

脱力のままでは手足が崩れて姿勢を保てないので、`real/pose_session.py` で **全 22 サーボに電源を入れ、その瞬間の関節角のまま保持**し、
ロボットを一体の箱として向きを変えて置いた（ユーザーが手で置く・支える）。各姿勢 5 秒記録。

保持した関節角は膝が約 40° 曲がった形（L7=−40.4°、L8=+44.5°、R7=−41.5°、R8=+37.7°）。
保持中の指令と実測の差は最大 3.85°（L2 左肩ロール、左向きで腕に体重がかかったとき）。中止の基準 5° には達しなかった。

5 姿勢での解: 誤差 prone 6.5° / supine 6.2° / left_down 27.5° / right_down 22.8° / upright 2.9° → **不合格**。

姿勢どうしのなす角を見ると、ずれの出どころが分かる。

| 組 | なす角 | 理想 | 読み取れること |
|---|---|---|---|
| left_down − right_down | 129.9° | 180° | 左右とも仰向け側へ 20〜30° 転がっていた（背中のケースで支えたため） |
| prone − supine | 168.3° | 180° | うつ伏せ・仰向けとも、直立の向きへ約 6° ずつ傾いていた（どちらも頭の側が約 6° 高い） |
| upright − prone / upright − supine | 84.3° / 84.1° | 90° | 同上（直立とは矛盾しない） |

upright・prone・supine の 3 つで解くと、誤差は upright 0.1°・prone 5.8°・supine 5.9° で、
残りは「寝かせたときに頭の側が約 6° 高い」置き方の傾きで説明できる。取り付け回転そのものはおおむね合っている見込みだが、
基準（< 3°）での確認はできていない。

## 不具合（ツール側）— 逆さの記録中に全サーボ脱力した

`pose_session.py` などの PC 側ツールは、送るパケットのシーケンス番号（0〜59999）を int16 の配列にそのまま入れていたため、
**32768 個目（保持を始めて約 5.5 分）で例外になって落ちた**。送信が止まったので、改造ファームの通信監視が
0.2 s で保持 → 1.2 s で全サーボ脱力に入った（**安全系は設計どおりに働いた**）。ユーザーが胴体を持って逆さにしていた最中で、
手足が急に脱力した。

直したこと: 3 つのツール（`fw_check`・`servo_jog`・`pose_session`）でシーケンス番号を uint16 として入れる。
32767〜123456 の番号で作って読み戻す回帰試験を `fw_check selftest` に追加。想定外の例外でも必ず脱力パケットを送ってから終えるようにした。

## 次（2 回目）

- 胴体の面の傾きをスマートフォンの水準器アプリなどで確かめながら置く（各姿勢 ±1〜2°）。
- 寝かせる姿勢は、頭の側が上がらないように腰・脚の側を支える（今回は頭の側が約 6° 高かった）。
- 左右は背中のケースが当たらないよう、胴体を手や箱で支えて胸の面を垂直にする。
- 膝を伸ばした形で保持すると置きやすい可能性がある。
- 逆さを取り直す。
