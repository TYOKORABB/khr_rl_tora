前回（11/10）の結果は `20261110_getup_r2/README.md`・`20261110_walk/README.md`、故障の分析は `20261110_getup_r2/servo_failure.md`。

扱わないこと: 重りの試験・ステップ応答（同期のテーマ）、質量・重心（はかりなし）。

## 目的

1. 交換したサーボと、ほかの腕のサーボが正常に動くことを確かめる。
2. 起き上がりの回数の確認をやり直す（11/10 は左肘の故障で途中まで）。
3. 左右の速さをやり直す（11/10 は故障の影響あり）。床の傾きも測る（右への流れの原因の切り分け、`20261110_walk/README.md`）。
4. 起き上がって歩くを、論文と発表に使えるように撮り直す。

## 交換のときに確かめること（研究室で交換する人と）

- 新しいサーボは、L 系統の 4 番（ICS の ID 4）にする。ID の設定には近藤の設定ソフト（ICS の USB アダプター）か、それができる道具が要る（本人の手元には多分ない）。
- 0 点と回転の向きは ESP32 の EEPROM（L4: cw +1、trm +91.00）で直しているので、ホーンを前と同じ向きに付ければ、EEPROM は書き換えずに済むはず。付けたあと、下の「始めの確認」で左右の肘の角度がそろうかを見る。
- 外したサーボは、研究室で単体で動かして確かめられるなら確かめる（故障の種類が分かる）。

## 起き上がりの回数の確認（結果を見る前に固定）

v12 シード 3（getup12-real-s3 model_5997）、`--seconds 8 --gap 0.08 --e-sat-deg 7 --freeze 5`、保持 3 秒。始める前に重力で姿勢を確かめる（ラベルと合わなければ動かさない）。

| 組 | 回数 | 書くこと |
|---|---|---|
| うつ伏せ | 4 | 8 秒以内に 1 秒続いた回数（「n 回中何回」） |
| 仰向け | 4 | 同上 |
| 仰向け寄りの横向き 左が下 | 3 | 同上 |
| 仰向け寄りの横向き 右が下 | 3 | 同上 |
| 連続（機体が自分で作る） | 8 | 同上（11/10 は 8 回中 8 回） |

- 読み方: 回数が少ないので成功率や有意差としては書かず「n 回中何回」で書く。11/9（v11b）・11/10（v12、故障の前）と並べるが、日と条件が違うので差の大きさは言わない。
- 無効: Wi-Fi の受信の途切れで止まった回、置き方がラベルと合わなかった回、**サーボの故障（下）と分かった回**（前の回までと分けて数え、全部の回数も書く）。
- サーボの故障の見分け方（11/10 の形）: どれかの関節が 3° 以上遅れ、電流の読みが 0.1 A 以下のまま 2 秒以上続く。各回のあとに確かめる（`python -m real.servo_failure_analysis` と同じ見方）。見つけたらその場で止め、順 1 の確認をやり直す。
