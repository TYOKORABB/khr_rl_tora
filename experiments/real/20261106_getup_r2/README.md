# 起き上がりの実機確認 1 回目（2026-11-06、研究室）

計画書 `docs/GetUpSim2RealPlan.md` §5.6 の R0（脱力のまま観測だけ）と、床の上での通電した起き上がり（R2 に当たる。吊り R1a は本人の判断で省いた）。
方策は sym のシード 1（`getup9-sym-s1` model_2999、左右反転のスイッチを使わない）。電源は AC アダプター（12 V・5 A・60 W）。
道具は `real/getup_session.py`（`shadow`・`sign-hand`・`getup`）。生データは `real/data/raw/`（git に入れない）。動画は本人がスマホで撮った（git に入れない）。

## 結論

- **4 回とも起き上がれなかった。** 胸は腕で持ち上がる（u は 0.99 以上を保ち、胴体の高さの推定は最大 0.17〜0.21 m）が、肩のピッチと肘が目標角の上限（測った角度 ± 0.05 rad）いっぱいで押し続けたまま回りきらず、腕と脚を体の下へ入れられない。足は宙に浮いたあと後ろへ伸び、腕立て伏せに近い形で止まる。
- **シミュでは同じ始めの姿勢から 64/64 で成功する**（1 回目の姿勢を個体差ありで再現）。始めの姿勢が難しいのではなく、実機とシミュの差。
- 床を滑りにくい面に替えても同じ（3 回目）。ずれの上限を 0.08 rad に広げると右肩は公称まで回り、本人の目でも「前より起き上がったように見える」が、成功しない（4 回目）。→ **関節の力（トルク）の不足が主な候補**。電源（5 A で足りるか）、サーボの硬さ・最大トルク、質量が候補で、まだ切り分けていない。
- 同じ失敗が 3 回続いたので、計画書の決まりどおり実機を止めて、シミュで原因を再現する。
- 安全: 4 回とも暴れ・中止なし。ループの周期は 20.0 ms（99 % 点 20.2 ms、GPU で学習を同時に回していた）。

## R0（脱力のまま、観測と方策の出力を記録）

| 姿勢 | 重力の向き（base 座標） | 期待とのずれ | 範囲の判定 |
|---|---|---|---|
| うつ伏せ | (0.991, 0.015, −0.132) | 7.6° | 関節角が NG（|z| 5.24） |
| 左が下 | (0.145, 0.983, −0.114) | 10.6° | 関節角が NG（|z| 5.21） |
| 右が下 | (−0.204, −0.977, 0.058) | 12.2° | 関節角・重力が NG（|z| 4.50、4.24） |

- 左右の向きは合っている（左が下で y が正）。
- 範囲の NG は、方策の観測の正規化が立った姿勢に寄っているため。学習の初期状態のバンクには、脚を後ろへ伸ばして足首を伸ばした形も 1077 個ある（股関節のピッチは範囲の内側）。
- **足首のピッチは、脱力すると −100° まで倒れ、学習の可動域（−90°）より 10° 深い。** 通電の始めに 1 秒かけて可動域の内側へ戻すようにした。

## 通電した起き上がり（各 8 秒 + 保持 3 秒）

始めはどれもうつ伏せで、腕は体の横に沿わせた。学習のうつ伏せは腕を前に出した形が中心だが、この形からもシミュでは成功する。

| 回 | 床 | ずれの上限 | u の最大 → 終わり | 胴体の高さの推定 最大 / 終わり | 上限いっぱいで押し続けた関節（1.5 秒以降） | 結果 |
|---|---|---|---|---|---|---|
| 1 | フローリングに近い研究室の床 | 0.05 rad | 0.998 → 0.953 | 0.184 / 0.177 m | 右肩ピッチ 100 %、右肘 92 % | 成功せず |
| 2 | 同上 | 0.05 rad | 0.999 → 0.919 | 0.213 / 0.185 m | 右肩ピッチ 86 %、左肩ピッチ 80 %、左肘 71 % | 成功せず |
| 3 | 滑りにくい面 | 0.05 rad | 1.000 → 0.950 | 0.165 / 0.155 m | 左肩ピッチ 98 %、左肘 96 %、右肩ピッチ 88 % | 成功せず |
| 4 | 滑りにくい面 | 0.08 rad | 0.996 → 0.953 | 0.203 / 0.184 m | 右肩ピッチ 61 %、右肩ロール 48 % | 成功せず |

- 胴体の高さの推定は、関節角と重力の向きからの順運動学（`khr_common/height_est.py`）。手足が床で滑ると実際の高さとは合わない。本人の目では 1 回目は「胴体は少しだけ浮く感じ」。
- 2 回目の動画（1〜6.5 秒を 2 コマ/秒で見た）: 胸は腕で持ち上がり、足は宙に浮いたまま体の下に入らない。5.5 秒ごろから脚を後ろへ伸ばして床に着け、腕立て伏せに近い形で止まる。
- 動画は 2・3・4 回目（本人のスマホ。作成時刻 14:49:59、14:59:28、15:01:41 で試行と対応。1 回目は撮っていない）。
- 3 回目の動画（滑りにくい面は灰色のタイルカーペット）: 2 回目と同じ。胸は腕で上がるが、足は宙に浮いたまま体の下に入らない。
- 4 回目の動画（ずれの上限 0.08 rad）: 5〜7 秒に体の向きが変わり、手足で体を支えて背中がカメラ側を向く姿勢まで上がる。記録でも鉛直まわりに 54° 回っている（2・3 回目は 3〜4°）。
  胴体の高さの条件を満たした時間は 75 %（2 回目 47 %、3 回目 0 %）。関節角の条件は 3 回とも一度も満たさず、公称から 17° 以上外れた関節は最も少ないときでも 5〜9 個。
- 比較動画（実機と、同じ始めの姿勢からのシミュ 2 本を並べる）: `getup/tools/real_vs_sim_video.py` → `media/videos/getup/real_vs_sim_<試行>.mp4`（git に入れない）。
  時刻は、動画で足が動き出したコマ（0.1 秒刻みで目で見た。2 回目 0.6 秒、3 回目 0.9 秒、4 回目 0.2 秒、±0.1 秒）を方策の開始に合わせた。手持ちの撮影でカメラが揺れるので、画面全体の差では自動で決められなかった。
- 中止の閾値（目標角とのずれ > 4.6° が 1 秒連続か累計 2 秒）は 1 度も働かなかった。目標角は測った角度 ± 上限に収めているので、関節が止まってもずれは上限（2.9°）を超えない。シミュのうつ伏せ 96 回では、この閾値で中止が働く試行は 0 だった（4.6° を超える連続の時間は 99 % 点で 0.04 秒、`getup_session` の閾値を決めた計算）。

## シミュで同じ失敗を再現する（11/6 夕方）

`getup/tools/real_repro_sweep.py`（CPU）。実機の 4 回の始めの姿勢から各 16 回（計 64 回）、個体差あり、8 秒。条件を 1 つずつ変えた。
「肩が上限近くで押した割合」は 1.5 秒以降、左右の肩ピッチで |送った目標角 − 角度| > ずれの上限 − 0.01 rad の割合（実機の記録と同じ見方）。

| 条件 | 成功 | 肩が上限近くで押した割合 | 最後の肩ピッチの公称からのずれ（中央値） |
|---|---|---|---|
| 学習と同じ（kp 25、トルクの上限 90 %） | 100 % | 0.3 % | 5.2° |
| トルクの上限 45 % | 100 % | 3.1 % | 4.7° |
| トルクの上限 30 % | 1.6 % | 40.9 % | 58.6° |
| 硬さ kp 12 | 20.3 % | 45.6 % | 6.0° |
| 硬さ kp 6 | 0 % | 72.6 % | 94.8° |
| 胴体を 0.4 kg 重く | 100 % | 1.4 % | 3.6° |
| kp 6 ＋ ずれの上限 0.08 rad | 0 % | 69.9 % | 90.8° |
| 参考: 実機の 4 回 | 0 % | 61〜100 % | 51〜92° |

- **実機と同じ失敗は、ずれの上限で出せる関節のトルクが 0.3〜0.4 N·m（シミュの 4 分の 1〜3 分の 1）のときに出る。** kp 6（0.05 rad で 0.30 N·m）と、トルクの上限 30 %（0.41 N·m）がそれに当たる。
  重さを 0.4 kg 増やしただけでは出ない。
- kp が低いのか、出せるトルクの上限が低いのかは、この比較では区別できない。実機で上限を 0.08 rad に広げると右肩は回りきった（4 回目）。
  これは硬さが低い側の見方に合うが、シミュの kp 6 ＋ 0.08 rad ではほとんど良くならず、1 回の実機だけでは決められない。
- 10/30 の確かめ（`docs/GetUpOverview.md` 7.1 節）で「上限 60 % でも成功は変わらない」としたのは、kp 25 のまま上限だけを下げたため。実機のサーボはもっと弱い可能性が高い。

### 強さの間の条件（11/6 夕方、比較動画を見て追加）

比較動画で、kp 6 のシミュは実機より弱すぎた（実機は 3 秒で胸を腕で持ち上げるが、kp 6 はほとんど伏せたまま）。
同じ道具に胴体の高さの最大（シミュの真の値）を足して、間の条件を比べた（実機の始めの姿勢 4 つ × 16 回）。

| 条件 | 成功 | 肩が上限近くで押した割合 | 最後の肩ピッチの公称からのずれ | 胴体の高さの最大（中央値） |
|---|---|---|---|---|
| kp 6 | 0 % | 74.8 % | 95.0° | 0.054 m |
| kp 8 | 0 % | 72.4 % | 93.7° | 0.057 m |
| kp 10 | 0 % | 69.8 % | 89.3° | 0.062 m |
| kp 12 | 20.3 % | 45.6 % | 6.0° | 0.192 m |
| トルクの上限 30 % | 14.1 % | 35.2 % | 56.8° | 0.134 m |
| トルクの上限 35 % | 50.0 % | 23.2 % | 3.0° | 0.193 m |
| トルクの上限 40 % | 90.6 % | 8.2 % | 3.1° | 0.194 m |
| 参考: 実機の 4 回 | 0 % | 61〜100 % | 51〜92° | 0.165〜0.213 m（関節角と重力からの推定） |

- **kp を下げた条件（6〜10）は、胸がほとんど上がらない（0.05〜0.06 m）。実機は胸が上がるので、硬さだけが低いという見方は実機と合わない。**
  kp 10 と 12 の間で急に変わる（成功 0 → 20 %、胴体の高さ 0.06 → 0.19 m）。
- **トルクの上限 30 % が実機にいちばん近い**（胸は途中まで上がり、肩は公称から 57° 外れたまま）。35 % で半分、40 % で 9 割が成功し、境目は 30〜40 % の間。
- 上限 30 % は 1 回目の比較では 1.6 %、今回は 14.1 %（どちらも 64 回）。個体差の乱数の引き方が違い、境目に近いので結果が揺れる。
- 歩行の四脚姿勢の保持で、指令と実測の差は全関節 0.72° 以内だった（`real/ROBOT_STATUS.md` の i）。小さな負荷では実機のサーボは十分硬い、という点も「硬さは足りていて、出せるトルクの上限が低い」側に合う。
- 見立て: **実機で出せる関節のトルクは仕様の 30〜35 % 前後（約 0.4〜0.5 N·m）。** 電源（12 V・5 A のアダプターで、サーボ数個が同時に全力を出すと電流が足りない）か、
  サーボの保護の設定（電流制限）が候補。次の実機で、起き上がり中の電圧と、サーボの電流制限の設定を確かめる。

## 次にやること

1. （11/6 夕方に済み、上の節）シミュで同じ失敗が出る条件: 関節のトルクが 0.3〜0.4 N·m に下がったとき。
2. 次の実機で、電源の電圧を起き上がり中に測る（5 A で足りているか）。サーボの設定（ストレッチ・電流制限、付録 A の e）を ICS マネージャで読む。
   あわせて、実機のサーボの硬さと出せるトルクを測る（腕に重りを下げて、たわみの角度を測るなど）。
3. 力の不足が原因と決まったら、学習の個体差に「サーボの強さ」を入れて学習し直すか、力の少ない起き上がり方を学ばせる。
