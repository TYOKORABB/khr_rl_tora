# khr-quadruped17 (v17) 検証結果 — ✅ 膝が動いた（主目的達成）／❌ 代償が大きい

- 記録日: 2026-07-31（学習: 4096env × 4000iter, seed=1, 所要 51分, 最終 model_3999。完走）
- 対策の意図は同ディレクトリ `investigation.md` を参照。
- 評価はノイズ/DR無効・loco座標系。前進は在範囲0.3。

## 1. 主目的: 膝が周期運動を始めた（大成功）

差分報酬（swing−stance）への修正が明確に効いた。**v16 の報酬ハックは再発していない。**

| 指標 | v15 | v16(ハック) | **v17** |
|---|---|---|---|
| l_knee ROM | 7.2° | 2.7° | **56.2°** |
| r_knee ROM | 7.8° | 2.8° | **54.7°** |
| 膝 swing−stance 差 (l/r) | — | +1.5 / +0.3° | **+12.6 / +13.8°** |
| l_knee 負荷 | 17% | 8% | **33%** |
| r_knee 負荷 | 15% | 9% | **38%** |
| l_ankle 負荷 | 24% | — | **14%** |
| r_ankle 負荷 | 22% | — | **18%** |

- **膝の可動域が 2.7° → 56.2° に激増**。v8 の 22.3° も大きく上回り、過去最大。
- **足首と膝の役割が逆転して正常化**: 膝(33〜38%) > 足首(14〜18%)。
  v13 以来の課題だった「脚が棒のまま足首を支点に振られる」状態が解消した。
- **後脚クリアランス 0.008/0.011 → 0.016/0.015 m**（目標 0.02 に接近）。
- 胴体の上下動も 1.8mm → **6.6mm** に増加。脚を畳んで胴が上下する、より歩行らしい動きになった。

## 2. 代償（いずれも実機を意識すると無視できない）

### ① トルクのピークが定格の 91% に上昇 ⚠️ 最重要

| 指標 | v16 | v17 |
|---|---|---|
| **ピーク \|τ\|** | 0.869 Nm (**63%**) | **1.246 Nm (91%)** @ r_knee_pitch |
| ピークが定格90%超の関節数 | 0/22 | **1/22** |
| duty>90%（時間割合）の関節数 | 0/22 | 0/22（**持続的な飽和は無い**） |
| 平均 \|τ\|/limit（前進/後退/横） | 15/14/12% | 17/15/13% |

**持続的な張り付き（duty）は 0/22 のままだが、瞬間ピークが r_knee で 91% に達した。**
膝を大きく速く動かす代償であり、「100%は絶対NG・負荷は低く」という要件に対して余裕が
9% しかない状態。実機投入前に必ず下げるべき。

### ② 追従性能の低下

| 方向 | v16 | v17 |
|---|---|---|
| 前進 | 75% | **62%** |
| 後退 | 69% | **49%** |
| 左横 | 62% | **48%** |
| 右横 | 65% | **48%** |
| 左旋回 / 右旋回 | 99 / 100% | 105 / 105% |

並進追従が全方向で 13〜20 ポイント低下（旋回は維持〜改善）。
膝の運動にコストを割いた分、指令速度の追従が犠牲になった。

### ③ 接地の質の更なる悪化（先送りしていた課題）

| 指標 | v14 | v15 | v16 | v17 |
|---|---|---|---|---|
| 後脚 足裏傾き（接地時平均） | 11.0° | 13.5° | 16.1° | **21.4°** |
| 足裏傾き 左/右 | 7.8/9.8° | 11.0/13.9° | 12.1/17.1° | **21.3/27.1°** |
| 後脚 接地滑り | 0.055/0.058 | 0.056/0.057 | 0.058/0.064 | **0.085/0.079** |

v15 で足裏水平罰を接地時のみにして以降、悪化が続いている。**v17 で 21.4° に達し、
v14 比で約2倍**。接地滑りも増加。investigation で「次版で扱う」と先送りした課題が
いよいよ無視できない水準になった。

### ④ 姿勢のドリフト（差分報酬の副作用）

| 指標 | 値 |
|---|---|
| 膝の平均角度 | **1.541 / 1.466 rad**（default 0.40） |
| base_z 平均 | **0.1791 m**（目標 0.1946） |

差分報酬は「swing と stance の差」しか見ないため、**膝の絶対角度は自由にドリフトできる**。
結果、膝が深く曲がった「沈み込み姿勢」に移行し、胴体高さも目標より 1.5cm 低くなった。
ハックは防げたが、**絶対姿勢は無拘束**という新たな性質が明らかになった。

| 項目 | 判定 |
|---|---|
| **膝の周期運動（主目的）** | ✅✅ **達成**（ROM 2.7→56.2°、swing−stance差 +13°） |
| 足首と膝の役割の是正 | ✅ 達成（膝33-38% > 足首14-18%） |
| 後脚クリアランス | ✅ 改善（0.008→0.016m、目標0.02に接近） |
| 報酬ハックの防止 | ✅ 成功（差分報酬は構造的にハック不可） |
| **トルクのピーク** | ❌ **91%まで上昇**（余裕9%。要対処） |
| 追従性能 | ❌ 低下（前進75→62%、後退69→49%） |

**結論: 「膝を動かす」という設計課題は解決した。差分報酬という設計則も実証できた。
ただし現状の v17 は代償が大きく、このままでは実機に載せられない。**
実機候補は依然 v15（追従・対称性・滑らかさが最良）。

## 5. 学び

- **差分（相対量）報酬はハックを防ぐが、絶対量は無拘束になる。**
  v16（絶対量→固定される）と v17（差分→絶対値がドリフト）は表裏の関係。
  実用的には **「差分で動きを促し、絶対量は別途ゆるく拘束する」** 組み合わせが要る。
- 望む挙動が得られた直後に、**別の指標（トルクピーク・接地の質・追従）が悪化する**のは
  この研究を通じた一貫した傾向。単一目的の最適化ではなく、常に多指標での確認が必要。

## 6. 次（v18 候補）

主目的は達成したので、**代償を戻す**フェーズに入るのが妥当。優先度順:

1. **膝の運動を適度に抑える**: `knee_swing_flexion` を 3.0 → 1.5〜2.0 に下げる。
   ROM 56° は過剰（v8 の 22° 程度が目安）。トルクピークと追従の同時改善が期待できる。
2. **接地の質の回復**（先送りしていた課題）: `feet_orientation` を「接地時＋着地直前」に広げる。
   膝が動くことは確認できたので、干渉リスクを取っても対処する価値がある。
3. **絶対姿勢の拘束**: 膝の絶対角度が default から離れすぎないよう緩く拘束する
   （`similar_to_default` の膝成分を強める等）。base_z も目標へ戻す。
